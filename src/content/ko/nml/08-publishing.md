# 모드 배포하기 :wbfireworks:

모드가 정상 작동합니다. 이제 다른 유저들이 버그를 찾아내게 만들 차례입니다.

월드박스 모드를 올릴 수 있는 곳은 크게 두 군데가 있으며, 이용률에는 상당한 차이가 있습니다:

| | |
| --- | --- |
| **[GameBanana](https://gamebanana.com/games/11196)** | 월드박스 모딩 씬의 진짜 중심지입니다. 스팀 외의 플랫폼에서 게임을 구매한 유저를 포함해 누구나 다운로드할 수 있습니다 |
| **Steam Workshop** | NML에 내장되어 있지만, 등록된 모드 수는 훨씬 적습니다 |

GameBanana에 먼저 배포하세요. 스팀 창작마당은 나중에 여유가 생기면 미러링하는 것을 권장합니다.

## 모드 패키징하기

GameBanana에 업로드하는 파일은 **모드 폴더를 그대로 압축한 zip 파일**입니다. 그 이상도 이하도 아닙니다. zip 파일 내부의 루트 폴더에 `mod.json`이 바로 들어 있어야 합니다:

```text HelloBox.zip
HelloBox/
├── mod.json
├── icon.png
├── default_config.json
├── Locales/
├── GameResources/
└── Code/
```

내용물만 모아서 zip으로 묶지 마세요. 반드시 **폴더 자체를 zip으로 묶어야** 합니다. 유저가 `Mods/` 디렉토리에 압축을 풀었을 때 `Mods/HelloBox/mod.json` 경로가 나와야 합니다. 만약 `Mods/mod.json`으로 풀리게 되면 모드가 로드되지 않는다는 항의 글이 올라오게 됩니다 :PES_Facepalm:.

실행에 필요 없는 파일은 **모두 제외**하세요: `.git/`, `bin/`, `obj/`, `.vs/`, `.sln` 파일, 개인 메모 등. 미리 빌드된 `.dll`을 배포할 때는 오래된 소스 코드와 함께 두지 말고, `Code/` 폴더 *대신* `.dll`만 포함시키세요.

## GameBanana에 업로드하기

1. 계정을 만든 후 **[WorldBox 게임 페이지](https://gamebanana.com/games/11196)**로 이동합니다.
2. **Add → Mod**를 클릭합니다.
3. 이름, 설명, 카테고리를 입력합니다. 카테고리는 생각보다 훨씬 중요합니다. 유저들이 여러분의 모드를 찾아내는 주된 경로이기 때문입니다.
4. zip 파일을 업로드하고, 적어도 한 장 이상 **모드가 인게임에서 실제로 무언가를 하고 있는 스크린샷**을 올리세요. 단순한 아이콘이나 모드 목록 스크린샷은 안 됩니다.
5. 설명란에는 무엇을 추가하는 모드인지, **NeoModLoader**가 필요하다는 사실, 충돌이 발생하는 다른 모드를 명확히 적어주세요.

이후 업데이트는 같은 페이지에서 **Edit → Files**로 진행합니다. 새 zip을 추가하고, 패치노트를 적고, `mod.json`의 `version`을 올려서 일치시킵니다. GameBanana 버전과 `mod.json`의 버전을 일치시키는 것은 품이 들지 않으면서도 유저들의 버전 혼란을 완전히 방지해 줍니다.

> [!TIP] 스크린샷 한 장이 백 마디 설명보다 낫습니다
> 유저는 썸네일을 보고 다운로드를 결정합니다. 모드가 추가하는 요소를 보여주는 깔끔한 인게임 스크린샷 한 장이 그 어떤 화려한 설명글보다 효과적입니다 :PES_Camera:.

## Steam 창작마당 업로드 경로

창작마당 업로드는 **게임 내부**에서 진행되며, 그 업로드 창을 여는 방식은 이 바닥에서 가장 기괴하고 저주받은 UI입니다 :kekw:.

1. 게임 내에서 **Mods** 창을 엽니다.
2. 내 모드의 **아이콘**을 1초 미만 간격으로 정확히 **8번 연속 클릭**합니다.
3. 약 3초 정도 기다립니다.
4. 업로드 창이 화면에 나타납니다.

아무 일도 일어나지 않는다면 클릭 속도가 너무 느렸거나, 아이콘 대신 목록 행 자체를 클릭한 것입니다.

새로운 NML 모드 목록 창에서는 선택한 모드의 폴더를 열거나 활성화/비활성화, 코드 핫 리로드를 수행하는 툴바 버튼을 제공하지만, 아이콘을 8번 연속 클릭하는 비밀 의식은 여전히 스팀 업로더를 여는 유일한 방법입니다 :PES2_Shrug:。

| 필드 | 입력할 내용 |
| --- | --- |
| 상단 필드 (`fileID`) | **최초 배포 시에는 비워둡니다**. 업데이트할 때는 창작마당 아이템 URL에 적힌 id를 붙여넣습니다 |
| 하단 필드 | 패치노트. 비워둬도 무방하며, 나중에 창작마당 웹 페이지에서 수정할 수 있습니다 |

신규 배포와 업데이트의 차이는 이것이 전부입니다. `fileID`가 비어 있으면 새 아이템을 생성하고, 채워져 있으면 기존 아이템을 덮어씁니다.

### 최초 인증 절차

창작마당에 새 모드를 올릴 때는 인증을 요구합니다. 세 가지 방법이 있습니다:

- **Discord**: 공식 WorldBox 디스코드의 관리자에게 요청하여 `Modder` 역할을 받습니다.
- **GitHub**: `WorldBoxOpenMods` 조직에 가입합니다. 제목을 "WorldBoxOpenMods"로 하고 GitHub 유저명과 모드 정보를 적어 메일을 보낸 뒤 최대 일주일 정도 대기합니다.
- **건너뛰기**: `Unverified Mods`(미검증 모드) 태그를 달고 그대로 업로드합니다. 정상 작동하지만 검색 노출도가 다소 낮아집니다.

## 업로드 버튼을 누르기 전 체크리스트

- **`mod.json`은 여러분의 쇼윈도입니다.** 유저가 읽는 것은 `name`, `author`, `version`, `description`입니다. 릴리즈마다 `version`을 올리고, 첫 업로드 이후에는 **절대로 `GUID`를 바꾸지 마세요**. 모드의 고유 주민등록번호이며, 유저의 설정 파일 이름이자 타 모드가 참조하는 기준점입니다.
- **`icon.png`를 꼭 만들고 정갈하게 다듬으세요.** 창작마당에서는 유저가 8번 두드려야 하는 대상이기도 하니 보기 좋게 만들어 두는 편이 좋습니다.
- **어떤 폴더명에서도 모드가 실행되어야 합니다.** `C:\Users\내이름\...` 같은 경로를 절대 하드코딩하지 마세요. `GetDeclaration().FolderPath`를 사용하세요. "내 컴퓨터에서는 잘 되는데 남의 컴퓨터에서는 안 되는" 압도적인 1위 원인입니다 :PES2_Bruh:.
- **로그를 처음부터 끝까지 정독하세요.** 게임을 켜고, 월드를 불러오고, 2분간 플레이한 뒤, `Player.log`에서 내 모드 접두사와 `Exception`을 검색해 보세요. 예외는 0개여야 합니다.
- **설정 파일을 지운 상태로 테스트하세요.** `mods_config/<GUID>.config` 파일을 삭제하여 신규 유저가 처음 마주할 기본 설정값으로 테스트해 보세요.
- **다른 모드들을 켠 채로 테스트하세요.** 여러분이 패치한 곳은 다른 누군가도 패치하고 있을 확률이 높습니다.
- **새 세이브 데이터에서 테스트하세요.** 등록한 에셋은 이를 참조하는 세이브 파일이 로드되기 전에 미리 등록되어 있어야 합니다.

## Dependencies

모드에 다른 선행 모드가 필요하다면, 클래스 누락으로 튕기게 두지 말고 종속성을 명시하세요:

```json mod.json
{
  "Dependencies": ["com.otherperson.coolmod"],
  "OptionalDependencies": ["com.someone.niceextra"],
  "IncompatibleWith": ["com.someone.rivalmod"]
}
```

NML이 로드 순서를 알아서 정렬하고 누락 시 유저에게 경고를 띄워줍니다. 1번 줄에서 널 포인터 에러로 튕기는 것보다 훨씬 친절합니다.

## 출시 후 관리

댓글란에는 정확히 세 종류의 글만 올라옵니다: 로그도 첨부하지 않은 "작동 안 해요", 미처 생각지 못했던 기가 막히게 멋진 아이디어, 그리고 멀티플레이를 만들어 달라는 사람 :PESgn_DidIAsk:.

두 번째 글에 답변을 집중하세요. 첫 번째 글에 대비해서는 `Player.log`의 위치를 안내하는 댓글을 고정해 두세요 (**[로그 및 디버깅](#/nml/logs-and-debugging)** 참고). 로그가 없는 버그 제보는 개발자로서 손쓸 방법이 없기 때문입니다.
