# 게임 업데이트 후 모드 업데이트하기 :wbsettingsgear:

WorldBox가 업데이트됐고, 여러분의 모드가 목록에서 빨간색이 됐습니다. 모딩에 오신 걸 환영합니다. 누구에게나 일어나는 일이고, 앞으로도 또 일어납니다 :PES2_Shrug:.

모드는 게임 자체의 코드를 호출합니다. 개발자가 메서드 이름을 바꾸거나, 필드를 옮기거나, 메서드가 받는 값을 바꾸면 여러분의 코드는 더 이상 존재하지 않는 것을 가리키게 됩니다. 고칠 수 없게 망가진 게 아니라 그냥 낡은 것입니다. 이 페이지는 제가 매번 확인하는 순서입니다.

## 1. 먼저 NML을 업데이트하기

자기 코드를 건드리기 전에 **[NML 설치](#/install-nml)** 페이지에서 최신 **`NeoModLoader.dll`** 을 받으세요. 큰 게임 업데이트에는 보통 새 NML도 따라오고, 오래된 로더를 새 게임에서 쓰면 딱 여러분의 실수처럼 보이는 방식으로 실패합니다.

NML 자체가 로드되지 않는다면 아직 모드 차례가 아닙니다. 문제 해결의 **[게임이 오래된 버전임](#/troubleshooting)** 을 먼저 보고 돌아오세요.

## 2. 첫 번째 오류 읽기

게임을 실행한 다음 `Player.log` 를 여세요 (위치: **[로그와 디버깅](#/nml/logs-and-debugging)**). 모드의 첫 번째 오류를 찾고, 그 아래는 일단 전부 무시하세요. 오류는 연쇄적으로 생기기 때문에, 첫 번째를 고치면 다른 다섯 개가 사라지는 일이 흔합니다.

업데이트 후에는 주로 이런 오류를 보게 됩니다:

| 오류 | 게임에서 바뀐 것 |
| --- | --- |
| `CS0117: 'X' does not contain a definition for 'Y'` | 필드나 정적 메서드의 이름이 바뀌었거나 삭제됨 |
| `CS1061: 'X' does not contain a definition for 'Y'` | 같은 경우지만 객체 쪽: `actor.someMethod()` 가 없어짐 |
| `CS0246: The type or namespace name 'X' could not be found` | 클래스 전체의 이름이 바뀌었거나 옮겨짐 |
| `CS7036` / `CS1501` | 메서드는 아직 있지만 이제 다른 인수를 받음 |
| `CS0122: 'X' is inaccessible due to its protection level` | 쓰던 것이 `internal` 이 됨. **[그 항목](#/troubleshooting)** 참고 |
| `CS0029` / `CS0266` | 필드의 타입이 바뀜. 예를 들어 `int` 에서 `float` 으로, 또는 문자열에서 에셋으로 |
| 시작할 때 `HarmonyException` / `MissingMethodException` | 여러분이 **패치하는** 메서드의 이름이 바뀜. 코드는 컴파일되지만 패치가 붙을 곳이 없음 |

마지막 것이 가장 교묘합니다. `"updateStats"` 처럼 메서드 이름을 그냥 문자열로 쓴 패치는 게임이 시작될 때만 확인됩니다. 그래서 이름이 바뀌어도 모드는 컴파일되고, 동작만 멈춥니다. `nameof` 로 쓴 패치는 대신 평범한 컴파일 오류가 나니, 쓸 수 있는 곳에서는 쓸 이유가 하나 더 생긴 셈입니다 (**[메서드 이름을 쓰는 두 가지 방법](#/nml/harmony-patches)**).

## 3. 새 이름 찾기

가장 흔한 고장: 메서드나 에셋 필드의 이름이 바뀐 경우입니다. `does not contain a definition for '...'` 라는 메시지와 함께 컴파일이 실패합니다.

옛 이름은 사라졌으니 대신할 것을 찾으세요:

- 이 사이트의 **[메서드 검색](#/tools/methods)**. 메서드 이름이 아니라 그 메서드가 *하던 일*을 입력하세요. "add trait to unit" 이라고 쓰면 이름이 바뀌었어도 찾아 줍니다.
- 에셋 필드는 **[에셋 필드](#/tools/fields)** 에서. 기억나는 부분의 이름으로 검색하세요.
- **dnSpy**. 여러분이 실제로 가진 게임을 읽기 때문에 항상 정확합니다. 이 사이트의 검색 도구는 업데이트 후 다시 만들어지지만, 막 나온 업데이트에는 며칠 늦을 수 있습니다. 사용법은 **[게임 코드 읽기](#/toolbox/reading-the-game-code)**.

제가 가장 많이 쓰는 요령: 여러분의 것과 같은 일을 하는 바닐라 에셋이나 메서드를 열어서, **게임 자신**이 지금 어떻게 쓰는지 보세요. 게임이 특성을 만드는 방식을 바꿨다면, 게임의 특성들은 이미 새 방식을 쓰고 있습니다 :PESgn_Noice:.

### 더 이상 존재하지 않는 이름들

오래된 모드, 옛날 튜토리얼, 과거 포럼 게시물에는 이런 이름들이 가득합니다. 현재 게임에는 이 중 어느 것도 존재하지 않으므로 각각 컴파일 오류를 일으키거나, 템플릿 ID의 경우 시작 시 `clone()` 에서 `KeyNotFoundException` 을 발생시킵니다:

| 옛 이름 | 지금 사용할 이름 |
| --- | --- |
| `AssetManager.unitStats` | `AssetManager.actor_library`. 생명체는 `ActorAsset`입니다. **[커스텀 액터](#/nml/custom-actors)** 참고 |
| `AssetManager.raceLibrary` | 직접적인 대체 항목이 없습니다. 예전에 race가 가지고 있던 정보는 이제 `ActorAsset` 자체에 있습니다 |
| `AssetManager.nameGenerator` | `AssetManager.name_generator`. **[이름 생성기](#/nml/name-generators)** 참고 |
| `AssetManager.items_material_weapon`, `items_material_accessory` | 대체 라이브러리가 없습니다. 각 재료는 `AssetManager.items` 내의 개별 아이템입니다 (`sword_iron`, `sword_steel`). **[커스텀 아이템](#/nml/custom-items)** 참고 |
| `"!building"` (건물 템플릿) | `AssetManager.buildings` 의 `"$building$"` |
| `"_spawn_building"` (드롭 템플릿) | `AssetManager.drops` 의 `"$spawn_building$"` |
| `"_dropBuilding"` (신의 권능 템플릿) | `AssetManager.powers` 의 `"$template_drop_building$"` |

마지막 세 항목의 패턴을 기억해 두세요: 템플릿은 이제 `$` 기호로 감싸집니다. 예전 `clone()` 에서 `_` 나 `!` 로 시작하는 ID를 쓰고 있다면, 같은 라이브러리의 `init()` 안에서 `$...$` 형태의 버전을 찾으세요.

## 4. Harmony 패치를 직접 확인하기

패치는 오류 하나 없이 망가질 수도 있습니다. 하나씩 보면서 dnSpy에서 메서드를 확인하세요:

- **매개변수 이름.** Harmony는 매개변수를 **이름으로** 채웁니다. 게임이 `pDamage` 를 `pAmount` 로 바꿨다면, 여러분의 `float pDamage` 가 더 이상 바인딩되지 않아 Harmony가 패치를 적용할 때 실패합니다. **[마법의 매개변수 이름](#/nml/harmony-patches)** 참고.
- **오버로드.** 전에는 하나뿐이던 메서드에 쌍둥이가 생겨서, 패치가 `Ambiguous match found` 로 실패할 수 있습니다.
- **메서드가 하는 일.** 이름은 그대로인데 로직만 다른 곳으로 옮겨가기도 합니다. 패치는 실행되는데 아무것도 바뀌지 않습니다. 패치에 `LogInfo` 한 줄을 넣어 보세요. 한 번도 찍히지 않는다면, 게임이 더 이상 그 메서드를 부르지 않는 겁니다.

## 5. 아무것도 하지 않게 된 것 찾기

다시 컴파일된다고 끝이 아닙니다. 월드를 불러와서 모든 부분이 아직 작동하는지 확인하세요: 특성에 아이콘이 보이고, 아이템이 떨어지고, 권능이 만들어야 할 것을 만드는지.

새 업데이트에서 바닐라 에셋은 채우는데 여러분의 것은 채우지 않는 필드가 생길 수 있습니다. 에셋은 로드되고, 오류도 없는데, 그냥 아무것도 안 합니다. 여러분의 에셋을 그 라이브러리의 `init()` 에 있는 가장 비슷한 바닐라 에셋과 필드별로 비교하세요. 게임은 이제 설정하는데 여러분은 설정하지 않은 것이 용의자입니다.

## 6. 오래된 세이브도 테스트하기

업데이트 **전에** 저장한 월드를 모드를 켠 채로 불러오세요. 유닛에 저장한 자체 데이터 (**[데이터 저장](#/nml/saving-data)**) 는 그대로 돌아와야 합니다. 고치다가 ID 이름을 바꿨다면, 오래된 세이브는 여전히 예전 ID를 쓰니 꼭 필요할 때만 바꾸세요.

## 7. 배포하기

- `mod.json` 의 `version` 을 올리세요.
- 설명과 변경 기록에 어떤 게임 버전에서 작동하는지 적어서, 플레이어가 어느 것을 받아야 할지 알게 하세요.
- 새 zip을 전과 같은 방법으로 올리세요: **[배포](#/nml/publishing)**.

그리고 "업데이트됐나요??" 댓글에 답해 주세요. 그럴 자격이 있습니다 :wbsalut:.

## 다음 업데이트를 덜 아프게

- **패치를 줄이세요.** Harmony 패치 하나하나가 망가질 수 있는 지점입니다. 에셋 필드나 NML 기능으로 해결된다면 그걸 쓰세요.
- **코드를 try/catch 로 감싸세요.** 망가진 기능은 로그에 오류를 하나 남길 뿐이고, 모드의 나머지는 계속 작동합니다. **[로그와 디버깅](#/nml/logs-and-debugging)** 참고.
- **작업 하나에 패치 클래스 하나.** 이렇게 하면 오류를 격리하기 쉬워집니다. 다만 `PatchAll` 오류까지 격리하지는 못합니다: 대상이 하나 누락되면 이후 패치가 적용되기 전에 스캔이 중단될 수 있습니다. 선택적 대상에는 방어 처리가 된 수동 패치를 사용하세요.
- **ID는 한곳에 모아 두세요.** `HelloTraits.SWIFT` 같은 상수가 있으면 이름 변경이 스무 군데가 아니라 한 군데 수정으로 끝납니다.
