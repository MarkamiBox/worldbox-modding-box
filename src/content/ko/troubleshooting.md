# 문제 해결 :wbfractured:

목록에서 증상을 찾아 클릭하고 3줄만 읽으세요. 이 페이지는 그것으로 끝입니다 :aPES2_ThumbsUp:.

> [!TIP] 로그를 확인하는 것이 가장 빠릅니다

## 모드 사용하기

이 그룹은 모드를 만드는 사람이 아니라 플레이하는 사람을 위한 것입니다. 이후의 내용은 코드를 작성하는 사람을 대상으로 합니다.

### 빨간 글씨가 화면을 뒤덮음

- **증상**: 화면에 빨간 글씨가 계속 흐르고 `previous errors repeated`, `YOU SHOULD RESTART THE GAME`이 표시되며, 로그에는 `Missing className: NeoModLoader (1).WorldBoxMod`가 남습니다.
- **원인**: 파일 이름이 `NeoModLoader.dll`이 아닙니다. 브라우저가 두 번째로 받을 때 이름에 ` (1)`을 붙이고, NML은 자신의 파일 이름을 직접 읽습니다.
- **해결**: 게임을 닫고, 오래된 사본을 지우고, 파일 이름을 정확히 `NeoModLoader.dll`로 바꾼 뒤 다시 시작하세요. 전체 과정은 **[NML 설치](#/install-nml)**에 있습니다.

### 업데이트 후 모드가 빨간색이나 실패로 표시됨

- **증상**: 모드 목록에서 모드가 빨간색, "failed", `current failed, will load`, `<Mod> has been disabled due to an error`로 표시됩니다. 업데이트 전에는 잘 작동했습니다.
- **원인**: 모드는 게임 자체의 코드를 호출합니다. WorldBox가 그 코드를 바꾸면 옛 버전용으로 만든 모드는 컴파일에 실패합니다. NML은 문제가 아니라 그저 전달자일 뿐입니다.
- **해결**: 해당 모드의 최신 버전을 찾아보세요 (GameBanana에서 **Updated** 순 정렬). 최신 버전이 없다면 제작자를 기다리거나 옛 버전 게임으로 플레이하세요, **[FAQ](#/install-nml)** 참고. 혹시 몰라 같은 모드를 두 개 넣어 두지 마세요: 서로 충돌합니다.

### 게임이 오래된 버전에 머물러 있음

- **증상**: NML이 아예 로드되지 않거나, 로그에 `MissingFieldException: Field not found: bool .Config.gameLoaded`가 나옵니다. 메인 메뉴의 버전 번호가 다른 사람들이 말하는 것보다 오래됐습니다.
- **원인**: 게임이 Steam **베타 브랜치**에 있습니다. 보통 예전에 업데이트를 미리 써보려고 선택해 둔 채로 남아 있으며, 받은 NML은 현재 버전용입니다.
- **해결**: Steam → WorldBox 우클릭 → **속성 → 베타** → **없음**. Steam이 업데이트하게 두고 Experimental Mode를 다시 켜세요 :PES2_Shrug:.

### 모드를 켜면 느려지거나 멈춤

- **증상**: FPS가 낮거나 끊기거나, 버튼은 반응하는데 월드만 멈춥니다. 모드 없이는 멀쩡합니다.
- **원인**: 거의 항상 매 틱마다 무거운 작업을 하는 모드 하나가 원인이며, 보통 큰 콘텐츠 모드입니다. 같은 것을 바꾸는 모드 두 개가 서로 잠기게 만들 수도 있습니다.
- **해결**: 모드 절반을 끄고 재시작해서 테스트하세요. 여전히 문제라면 켜져 있는 절반 안에 범인이 있습니다. 하나만 남을 때까지 절반씩 좁혀 나가세요. 끄는 것만으로 충분하며 지울 필요는 없습니다. 그 모드 설명에서 알려진 비호환성을 확인하고, 같은 모드의 정식판과 "라이트"판을 동시에 켜지 마세요.

### 월드가 더 이상 로드되지 않음

- **증상**: 세이브를 열면 다른 월드가 뜨거나, 로딩 중 멈추거나, 저장/로드 중 `NullReferenceException`이 발생합니다.
- **원인**: 월드 안에 지금은 꺼져 있거나 삭제되거나 오래된 모드의 생물, 건물, 특성이 들어 있습니다. 게임이 모르는 id를 발견한 것입니다.
- **해결**: 그 모드를 다시 켜거나 (또는 세이브를 만들었던 버전으로 돌아가서) 월드를 불러온 뒤, 모드 콘텐츠를 게임 내에서 제거하고 나서 모드를 지우세요. 새 콘텐츠 모드를 시도하기 전에 아끼는 월드는 복사해 두세요 :PES_MonkaSweat:.

### BepInEx 모드를 넣었는데 아무것도 안 보임

- **증상**: 모드가 `BepInEx/plugins`에 있는데 게임에 아무것도 나타나지 않고, `BepInEx/config`에 전용 설정 파일도 생기지 않습니다.
- **원인**: zip 파일 자체를 `plugins`에 넣었거나, BepInEx의 매니저 오브젝트가 게임에 의해 파괴되고 있습니다 (일부 환경에서는 설정이 필요합니다).
- **해결**: zip **안에 든 폴더**를 `BepInEx/plugins`에 넣으세요, zip 자체가 아닙니다. 그다음 `BepInEx/config/BepInEx.cfg`를 열어 `HideManagerGameObject = false`를 찾아 `true`로 바꾸고 저장 후 재시작하세요. BepInEx 자체 설치는 **[실시간 콘솔](#/toolbox/bepinex-console)** 참고.

### 모드를 지웠는데 아직 남아 있음

- **증상**: `Mods`에서 폴더를 지웠는데도 그 모드가 계속 로드됩니다.
- **원인**: Steam Workshop에서 구독한 모드입니다. Workshop 모드는 여러분의 폴더가 아니라 Steam 자체 폴더에 있습니다.
- **해결**: Workshop 페이지에서 구독을 취소하세요. 목록에서 체크만 해제하는 것으로는 부족합니다.

### 게임이 아예 시작되지 않음

- **증상**: 모드를 다 빼도 WorldBox가 메인 메뉴 전에 닫히거나 멈춥니다.
- **원인**: 게임 자체 파일이 손상되었으며, 보통 무언가를 잘못된 폴더에 복사해서 생깁니다.
- **해결**: Steam → WorldBox 우클릭 → **속성 → 설치된 파일 → 게임 파일 무결성 검사**. 그다음 NML과 모드를 하나씩 다시 넣으세요.

## 아무것도 로드되지 않음

게임이 마치 여러분의 모드가 없는 것처럼 굽니다. 개인적인 감정은 아니고, 보통은 스위치 하나나 파일 이름 하나 문제입니다.

### 메뉴에 Mods 버튼이 없음

- **증상**: 게임은 멀쩡히 시작되고, 오류도 없고, Mods 버튼도 없고, 로그 어디에도 `[NML]` 줄이 없습니다.
- **원인**: "Mods"라는 폴더가 두 개 있습니다. 로더 DLL은 게임 데이터 폴더에 들어가고, `worldbox\Mods/`는 *여러분의* 모드용입니다.
- **해결책**: `NeoModLoader.dll`을 `worldbox\worldbox_Data\StreamingAssets\mods/`에 넣고 재시작한 뒤, 로그에서 `[NML]: NeoModLoader Version:`을 찾으세요. Mac을 포함한 모든 클릭 과정: **[NML 설치](#/install-nml)**.

### Mods 창이 비어 있음 (이전에는 작동함)

- **증상**: 창은 열리지만 목록이 비어 있음.
- **원인**: **실험 모드(Experimental Mode)가 꺼져 있음**. 게임 업데이트 시 자동으로 꺼집니다.
- **해결책**: 설정 → 실험 모드 → 켜기 → 재시작.

### 모드 폴더는 있지만 목록에 나타나지 않음

- **증상**: 목록에 아무것도 없고, `Compile Mod <yours>` 줄도 없습니다.
- **원인**: 자주 일어나는 순서대로: 파일이 사실은 `mod.json.txt`임; JSON이 잘못됨(마지막 항목 뒤의 쉼표, 또는 채팅 앱에서 붙여 넣은 둥근 `"` 따옴표); 폴더가 `worldbox\Mods/` 안에 없음.
- **해결책**: 탐색기 → **보기 → 표시 → 파일 확장명**을 켠 다음 진짜 이름을 확인하세요. `mod.json`은 JSON 오류에 밑줄을 그어 주는 VS Code에서 여세요.

### 모드가 회색으로 비활성화됨

- **증상**: 회색으로 표시되고, 여러분의 코드가 하나도 실행되지 않습니다.
- **원인**: 비활성화되어 있으며, 그 상태가 디스크의 `StreamingAssets\mods\NML\mod_compile_records.json`에 기억되어 있습니다.
- **해결책**: Mods 창에서 모드 아이콘을 클릭한 뒤 재시작하세요.

### "Compile failed" 오류가 이해되지 않음

- **증상**: `Code\Main.cs(9,42): error CS1002: ; expected` 다음에 요약 줄이 나옵니다.
- **원인**: 요약은 오류가 아닙니다. 그 위의 줄이 오류이며, 파일, 줄, 열을 알려 줍니다.
- **해결책**: **첫 번째** 오류만 고치고, 재시작해서 다시 보세요. 오류는 연쇄적으로 생깁니다.

| 코드 | 의미 |
| --- | --- |
| `CS1002` | `;`가 빠짐 |
| `CS0246` | 모르는 이름. 보통 `using`이 빠진 경우 |
| `CS0266` | 정수 자리에 소수를 넣음(`int`에 `0.5f`) |
| `CS0122` | 해당 멤버가 `internal`입니다. [그 항목](#cs0122-inaccessible-due-to-its-protection-level)을 보세요 |

### 방금 붙여넣은 파일의 1번째 줄에서 오류 발생

- **증상**: 1번 줄에서 말도 안 되는 것 같은 컴파일 오류가 납니다.
- **원인**: 이 사이트의 코드 블록에는 파일 경로 라벨이 붙어 있습니다. 조금만 더 위까지 선택하면 그 라벨이 `.cs` 안에 들어갑니다.
- **해결책**: 1번 줄을 지우세요. `.cs`는 `using`, `namespace` 또는 클래스로 시작하고, `mod.json`은 `{`로 시작합니다.

### 코드를 수정했는데 게임에 반영되지 않음

- **증상**: 예전 동작 그대로이고, 오류도 없습니다.
- **원인**: NML은 `Code\*.cs`를 **시작할 때 한 번만** 컴파일합니다. 실행 중인 게임은 파일을 다시 읽지 않습니다.
- **해결책**: 저장하고, 완전히 종료한 뒤, 다시 시작하세요. 재시작 한 번에 변경은 하나만. 그래야 망가졌을 때 용의자가 하나입니다.

### 메모장에서 게임 폴더에 저장이 안 됨

- **증상**: 재시작하면 로그에는 `Compile Mod`라고 나오는데, 게임은 여전히 예전 코드를 실행합니다. 컴파일은 순식간에 끝납니다.
- **원인**: `Mods/` 안의 두 폴더가 `mod.json`에서 같은 `GUID`를 가지고 있습니다. 보통은 NML 설치 프로그램이 `COM_YOURNAME_HELLOBOX/`로 풀어 놓은 예전 복사본입니다. NML은 **GUID마다 모드 하나만** 불러오고 다른 폴더는 조용히 무시하는데, 그게 바로 여러분이 수정하고 있는 폴더일 수 있습니다.
- **해결책**: `Mods/`에서 여러분의 GUID를 검색하고 폴더를 정확히 하나만 남기세요. 뭔가 계산이 안 맞는다면 가장 먼저 확인할 부분입니다.

### 다시 시작해도 수정한 내용이 반영되지 않는다

- **증상**: "이 위치에 저장할 권한이 없습니다"라며 대신 문서 폴더를 권합니다.
- **원인**: 게임은 Windows가 보호하는 `C:\Program Files (x86)/` 아래에 있습니다.
- **해결책**: 먼저 탐색기에서 파일을 만들고(오른쪽 클릭 → 새로 만들기 → 텍스트 문서, 이름 바꾸기), 그렇게 만들어진 파일을 편집하세요.

## 로드는 되지만 아무것도 나타나지 않음

NML은 여러분의 모드를 찾아서 실행했습니다. 그 안의 무언가가 화면까지 오지 못했을 뿐입니다.

### 스탯을 설정하는 줄에서 크래시 발생

- **증상**: `Initialize()` 안에서 `NullReferenceException`이 나고, 그 뒤의 모든 것이 실행되지 않습니다.
- **원인**: 새로 만든 에셋에는 **스탯 블록이 없습니다**. 라이브러리가 `add()` 안에서 만듭니다.
- **해결책**: `add()`가 먼저, 스탯은 그다음. 특성, 상태 효과, 아이템, 건물, 액터 모두 같은 규칙입니다.

```csharp
ActorTrait swift = new ActorTrait { id = SWIFT, group_id = "physique" };
AssetManager.traits.add(swift);      // 여기서 base_stats가 생성됨
swift.base_stats["speed"] = 20f;     // 이제 안전하게 접근 가능
```

`clone()`은 `add()`를 대신 호출하므로, 클론한 뒤에는 블록이 이미 존재합니다.

### 순서가 맞는데도 동일한 크래시 발생

- **증상**: 같은 `NullReferenceException`이, `add()` 이후에 실행되는 스탯 줄에서 납니다.
- **원인**: 스탯 이름을 지어냈습니다. 알 수 없는 스탯 ID는 아무 일도 안 하는 게 아니라 크래시입니다.
- **해결책**: 진짜 ID를 쓰세요: `damage`, `health`, `speed`, `armor`, `attack_speed`, `stamina`, `mana`, `range`, `critical_chance`, `lifespan`, `warfare`. 배율은 따로 있습니다: `multiplier_damage`, `multiplier_health`, `multiplier_speed`. 전체 목록은 **[스탯 레퍼런스](#/nml/stats)**에 있습니다.

### 건물이 즉시 파괴되거나 크기가 없음

- **증상**: 건물이 나타났다가 사라지거나, 대상으로 지정할 수 없습니다. 오류는 없습니다.
- **원인**: 건물의 기본 `health`와 `size`는 `add()` 안에서만, 그것도 `base_stats`가 아직 null일 때만 설정됩니다. 먼저 블록을 직접 만들면 `health = 0`이 됩니다.
- **해결책**: `base_stats`를 미리 만들지 마세요. 먼저 클론하거나 `add()`한 뒤, 달라야 하는 것만 바꾸세요.

### 등록은 되었으나 어떤 탭에도 보이지 않음

- **증상**: 로그 줄은 찍히고 예외도 없는데, 어느 카테고리에도 없습니다.
- **원인**: `group_id`가 존재하지 않는 그룹을 가리켜서, 그려 넣을 탭이 없습니다.
- **해결책**: 진짜 그룹 ID를 쓰세요. 액터 특성: `cognitive`, `mind`, `spirit`, `physique`, `health`, `body`, `appearance`, `protection`, `skills`, `merits`, `acquired`, `fun`, `fate`, `miscellaneous`, `special`. 여러분만의 탭: **[특성 그룹과 탭](#/nml/trait-groups)**.

### 이름 대신 `trait_hello_swift`가 표시됨

- **증상**: 화면에 날것의 키가 나오고, 툴팁은 비어 있고, 로그에 `missing text:`가 찍힙니다.
- **원인**: 번역이 등록되지 않았습니다. 게임은 키를 스스로 만듭니다: `trait_<id>`와 `trait_<id>_info`.
- **해결책**: 그 두 키를 `Locales/en.json`에 추가하세요. `en.json.txt`를 조심하세요.

### 특성은 이름이 나오지만 아이템/상태/파워는 안 나옴

- **증상**: 특성 방식을 그대로 따라 했는데 이것만 여전히 날것의 키로 보입니다.
- **원인**: 네 가지 에셋은 ID로 키를 만들지 **않습니다**:

| 에셋 | 이름 키 | 설명 키 |
| --- | --- | --- |
| `GodPower` | `name` **필드**, snake_case | `<name>_description` |
| `ItemAsset` | `translation_key`, 없으면 `item_<subtype or id>` | `<id>_description`, `item_` 없음 |
| `StatusAsset` | `locale_id` **필드** | `locale_description` **필드** |
| `WorldLawAsset` | `<id>_title` | `<id>_description` |

- **해결책**: 권능에는 `name` = ID를, 아이템에는 `translation_key`를, 상태 효과에는 `locale_id`를 설정하세요. 키는 소문자 snake_case로 두세요: 저장할 때는 정규화되지만 찾을 때는 **정규화되지 않으므로**, `MyKey`는 `my_key`로 저장되고 다시는 찾을 수 없습니다 :PESgn_SMH:.

### 아이콘이 빈 투명 공간으로 나옴

- **원인**: 잘못된 경로는 `null`을 반환하며 세션 동안 캐시됩니다.
- **해결책**: 확장자 없이 슬래시(`/`)로 `path_icon`을 설정하고 재시작하세요.

### 버튼 공간은 차지하지만 아무것도 그려지지 않음

- **증상**: 탭에 아무도 클릭하지 않을 빈자리가 생깁니다.
- **원인**: `null` 스프라이트는 자리 표시자가 아니라, 그냥 아무것도 아닙니다 :PES4_Invisible:.
- **해결책**: 스프라이트를 확인 없이 넘기지 마세요. `ui/Icons/iconQuestionMark`로 대체하면 한눈에 "경로가 틀렸다"는 걸 알 수 있습니다. 도우미는 **[권능 탭과 버튼](#/nml/power-buttons)**에 있습니다.

### 상태 효과 스프라이트가 유닛에 표시되지 않음

- **증상**: 생물 위에 아무것도 안 그려지거나, 상태가 지속되는 동안 **매 프레임** `Status.updateAnimationFrame()` 에서 `NullReferenceException` 이 난다.
- **원인**: `StatusLibrary` 는 게임 로드 중 한 번에 `"effects/" + texture` 로 `sprite_list` 를 채우고 `need_visual_render` 를 켭니다. 모드보다 먼저입니다. 게다가 `texture` 는 PNG 하나가 아니라 프레임 **폴더** 의 이름입니다.
- **해결책**: 프레임을 `GameResources/effects/fx_hello_status/` 에 두고, `add()` 다음에:

```csharp
cursed.sprite_list = SpriteTextureLoader.getSpriteList("effects/" + cursed.texture);
cursed.need_visual_render = true;
```

### 버튼들이 서로 겹쳐서 표시됨

- **원인**: `recalc()`만으로는 위치 정렬이 되지 않습니다.
- **해결책**: `tab.recalc();` 후 `tab.sortButtons();`를 연속으로 호출하세요. 단, `OnModLoad` 안에서는 안 됩니다. 거기서 `recalc()` 를 부르면 죽습니다. **[권능 탭이 나타나지 않는다](#권능-탭이-나타나지-않는다)** 를 보세요.

### 버튼은 있으나 클릭해도 파워가 작동하지 않음

- **증상**: 커서가 바뀌지 않고, 지도를 클릭해도 아무 일도 없습니다.
- **원인**: 버튼은 **만들어지는 순간에, ID로** 권능에 연결됩니다.
- **해결책**: 권능을 먼저 등록하고, 버튼은 그다음에 만드세요. 순서가 어긋나지 않게 같은 도우미 안에서요. 그리고 `click_action`은 `(WorldTile, string)`입니다. `(WorldTile, GodPower)` 형태는 `click_power_action`의 것입니다.

### `addOpposite` / `addDecision` / `addSpell`이 작동하지 않음

- **증상**: 반대 특성이 절대 제거되지 않고, 결정이 절대 발동하지 않습니다. 아무 메시지도 없습니다.
- **원인**: 이 호출들은 **ID**만 추가합니다. ID를 실제 객체로 바꾸는 일은 여러분의 모드가 로드되기 전, 시작할 때 한 번만 일어납니다.
- **해결책**: `add()` 다음에 해석된 필드를 직접 채우세요: `linkCombatActions()`, `linkSpells()`, `decisions_assets`(`AssetManager.decisions_library.get()`으로 직접 만드는 배열이며, 연결 메서드는 없습니다), 그리고 `opposite_traits`는 직접 대입하세요. `opposite_trait_mod`를 설정하고 `opposite_traits`를 null로 두면 나중에 게임의 사회 관련 코드 안에서 크래시가 납니다. 빈 `HashSet`이면 막을 수 있습니다.

## 등록은 됐는데 월드에서 깨진다

이 섹션의 모든 항목은 원인이 같습니다. 게임은 각 에셋의 일부를 **로드 중에 한 번만** 준비하고, 모드는 그 뒤에 에셋을 등록합니다. 아무도 알려주지 않습니다. 에셋은 존재하고 이름도 있는데, 게임이 처음 실제로 쓰는 순간 예외가 납니다. 해결도 늘 같은 모양입니다. 에셋을 등록한 직후에 그 한 단계를 직접 하세요 :wbfacepalm:. 오늘의 단어: 우회책.

### 생물이 그림자 에러를 낸다

- **증상**: `ActorAssetLibrary: Shadow size is too small : (0.00, 0.00)` 이 생물마다 세 번, 게임 안에 에러 팝업.
- **원인**: 라이브러리는 시작할 때 모든 액터의 그림자 스프라이트를 잽니다. 나중에 추가한 생물은 한 번도 재지 않습니다.
- **해결책**: 복제한 뒤 `asset.texture_asset.loadShadow();`. **[커스텀 액터](#/nml/custom-actors)** 참고.

### 특성, 아이템, 생물이 계속 잠겨 있다

- **증상**: 존재는 하지만 지식의 책에 회색으로 보이고, 월드에서 나타나기 전까지 플레이어가 쓸 수 없다.
- **원인**: 잠금 해제가 가능한 모든 것은 `needs_to_be_explored` 가 기본값 `true` 입니다. 액터, 일곱 종류 특성, 아이템, 아이템 수식어, 월드 법칙.
- **해결책**: 만들 때 `needs_to_be_explored = false`. **[커스텀 특성](#/nml/custom-traits)** 참고.

### 무기나 음식을 불러오다 게임이 죽는다

- **증상**: `ItemLibrary.loadSprites()` 또는 `ResourceLibrary.loadSprites()` 에서 `ArgumentNullException: Value cannot be null. Parameter name: key`.
- **원인**: 무기의 `path_gameplay_sprite` 와 자원의 `full_sprite_path` 는 게임 자신의 로드 중 `post_init()` 에서 유도됩니다. 당신 것은 `null` 로 남습니다.
- **해결책**: 직접 설정하세요. **[커스텀 아이템](#/nml/custom-items)** 과 **[자원과 음식](#/nml/resources)** 참고.

### 구름이 나타나자마자 죽는다

- **증상**: 구름이 처음 나타날 때 `Cloud.prepare()` 에서 `NullReferenceException`.
- **원인**: `CloudLibrary` 는 시작할 때 한 번에 `path_sprites` 를 `cached_sprites` 로, `color_hex` 를 `color` 로 바꿉니다.
- **해결책**: `add()` 다음에 둘 다 직접 하세요. **[구름과 날씨](#/nml/clouds)** 참고.

### 건물을 놓으면 Index was out of range

- **증상**: 하나를 놓는 순간 `Building.setAnimData()` 에서 `ArgumentOutOfRangeException: Index was out of range`.
- **원인**: 건물 프레임은 시작할 때 모든 건물에 대해 미리 불러옵니다. 당신 건물은 프레임 목록이 비었거나, 폴더에 `main_0.png` 가 없습니다.
- **해결책**: `sprite_path` 를 정한 뒤 `shrine.loadBuildingSprites();`, 프레임 이름은 `main_0`, `construction_0`, `ruin_0`, `mini_0`. **[커스텀 건물](#/nml/custom-buildings)** 참고.

### 건물이 화면에 보이는 매 프레임 예외를 낸다

- **증상**: `DynamicSprites.getRecoloredBuilding()` 에서 `NullReferenceException` 수백 개, 화면에 있는 동안 프레임마다 하나.
- **원인**: 건물을 주인 색으로 칠하는 아틀라스 `atlas_asset` 은 시작할 때 `checkAtlasLink()` 에서 연결됩니다. 복제본은 이걸 유지하지 않습니다.
- **해결책**: `shrine.atlas_asset = AssetManager.dynamic_sprites_library.get(shrine.atlas_id);`

### 건물이 생기면 미니맵이 예외를 낸다

- **증상**: 미니맵을 다시 그릴 때마다 `Building.getColorForMinimap()` 에서 `NullReferenceException`.
- **원인**: 미니맵의 점은 건물 폴더의 `mini_0.png` 에서 나오는데, 그게 없습니다.
- **해결책**: `mini_0.png` 를 추가하세요. 건물이 차지하는 타일 하나당 1픽셀이고, `temple_human` 에서 복제한 건 5x4 입니다.

### 타일은 칠해지는데 맵 렌더러가 예외를 낸다

- **증상**: 화면에 있는 당신 타일마다 `WorldTilemap.getVariation()` 에서 `NullReferenceException`.
- **원인**: `TopTileLibrary` 는 시작할 때 `tiles/<id>/` 의 PNG 를 `sprites` 로 불러옵니다.
- **해결책**: `addVariation()` 으로 직접 불러오세요. **[타일과 지형](#/nml/tiles)** 참고.

### 당신 타일에 동물을 스폰하면 죽는다

- **증상**: `Subspecies.generateName()` 에서 `NullReferenceException`, 당신 타일에서만, 동물일 때만.
- **원인**: 풀 타일의 복제본은 `is_biome = true` 는 유지하지만 `biome_asset` 은 잃습니다. 이건 시작할 때 `linkAssets()` 에서 연결되는 값입니다. 동물은 종 이름에 바이옴을 붙입니다.
- **해결책**: `moss.biome_asset = AssetManager.biome_library.get(moss.biome_id);`

### 드롭이 안 보이게 떨어지거나 투사체가 예외를 낸다

- **증상**: 드롭이 아무것도 안 그려진 채 떨어지거나, `QuantumSpriteLibrary.drawProjectiles()` 에서 `ArgumentOutOfRangeException`.
- **원인**: 드롭, 투사체, 상태, 건물, 손에 든 자원은 `getSpriteList()` 로 그림을 읽는데, 이건 폴더 *안의* 프레임을 돌려줍니다. PNG 하나는 빈 목록이 됩니다.
- **해결책**: 프레임이 하나여도 애니메이션마다 폴더 하나: `drops/hello_ember/hello_ember_0.png`. **[스프라이트와 리소스](#/nml/sprites-and-resources)** 참고.

### 투사체의 ArgumentNullException 으로 로그가 가득 찬다

- **증상**: 투사체가 날아가는 동안 `ProjectileManager.updateProjectiles()` 에서 `ArgumentNullException: Value cannot be null` 이 수천 번.
- **원인**: 쏜 쪽이 없는 투사체에는 왕국이 없고, 매니저는 매 프레임 왕국을 딕셔너리 키로 씁니다.
- **해결책**: 왕국을 주세요: `pForcedKingdom: World.world.kingdoms_wild.get("nature")`, 게임 자신의 중립 소유자입니다.

### 권능 탭이 나타나지 않는다

- **증상**: `PowersTab.setNewWidth()` 에서 `NullReferenceException`, 탭도 없고 권능도 없다.
- **원인**: `OnModLoad` 안에서 `recalc()` 를 불렀습니다. 탭 자신의 `Start()` 가 아직 안 돌아서 부모가 `null` 이고, 예외가 단계 전체를 죽입니다.
- **해결책**: 탭은 로드 때 만들고 배치는 `Update()` 에서. **[권능 탭과 버튼](#/nml/power-buttons)** 참고.

### 설정 창에 날것 id 가 보인다

- **증상**: 로그에 `LocalizedTextManager: missing text: strike_radius Description`.
- **원인**: NML은 설정의 각 줄에 키 두 개를 요청합니다. 라벨용 `<id>` 와 툴팁용 `<id> Description` (띄어쓰기와 대문자 D).
- **해결책**: 둘 다 `Locales/en.json` 에 추가하세요. **[모드 설정](#/nml/mod-config)** 참고.

### 월드 비헤이비어를 추가한 후 매 프레임 예외 오류가 발생함

- **증상**: 모드가 로드된 순간부터 매 프레임 `MapBox.updateWorldBehaviours()`에서 `NullReferenceException`이 발생합니다.
- **원인**: 월드는 맵이 처음 로드될 때(모드 로드 전) 비헤이비어당 하나의 타이머를 생성합니다. 새로 추가된 비헤이비어에는 타이머가 없지만 루프가 이를 그대로 호출합니다.
- **해결법**: `add()` 직후에 `behaviour.manager = new WorldBehaviour(behaviour);`를 실행하세요. **[세계의 시대와 월드 비헤이비어](#/nml/world-ages)**를 참조하세요.

### 재앙이 월드 로그에 기록할 때 크래시 발생

- **증상**: `WorldLog.logDisaster()`에서 호출되는 `WorldLogMessage` 생성자에서 `NullReferenceException`이 발생합니다.
- **원인**: `world_log`는 텍스트 키가 아니라 `WorldLogAsset`의 ID입니다. 등록되지 않은 ID는 `null`을 반환하며 메시지가 이를 기반으로 생성되다 크래시가 납니다.
- **해결법**: 해당 ID로 `$basic_disaster$`를 복제하고 `locale_id`를 설정하세요. **[재앙](#/nml/disasters)**을 참조하세요.

### action이 없는 재앙이 선택되었을 때 크래시 발생

- **증상**: 재앙 추첨이 내 재앙에 당첨되었을 때 `WorldBehaviourActions.updateDisasters()`에서 `NullReferenceException`이 발생합니다.
- **원인**: 추첨 시스템이 null 체크 없이 `action`을 호출합니다. `spawn_asset_unit`만으로는 아무것도 실행되지 않습니다.
- **해결법**: `action`을 `AssetManager.disasters.simpleUnitAssetSpawnUsingIslands`로 지정하거나 커스텀 액션을 작성하세요.

### 지도자가 내 음모를 검토할 때 크래시 발생

- **증상**: `PlotAsset.checkIsPossible()`에서 `NullReferenceException`이 발생합니다.
- **원인**: 지도자가 음모를 검토할 때마다 `check_is_possible`이 null 체크 없이 호출됩니다.
- **해결법**: 항상 설정해 두세요. 조건이 없다면 `true`를 반환하세요. **[음모](#/nml/plots)**를 참조하세요.

### 결정, 음모, 유전자, 무기가 존재하지만 게임에서 절대 사용되지 않음

- **증상**: 오류는 없습니다. 에셋은 라이브러리에 있지만 게임이 이를 선택하지 않습니다.
- **원인**: 게임은 시작 시 빌드된 목록(`basic_plots`, 결정 목록, 유전자 변이 풀, 무기 풀, 시대의 슬롯 풀 등)에서 선택합니다. 내 에셋은 시작 후에 추가되었습니다.
- **해결법**: 게임이 실제로 읽는 목록에 추가하세요. 각 페이지에서 설명합니다: **[커스텀 AI](#/nml/custom-ai)**, **[음모](#/nml/plots)**, **[아종 특성](#/nml/subspecies-traits)**, **[커스텀 아이템](#/nml/custom-items)**, **[세계의 시대와 월드 비헤이비어](#/nml/world-ages)**.

## 내 PC에서는 되는데 다른 사람 PC에서는 안 됨

고전적인 "제 컴퓨터에선 되는데요". 차이는 보통 코드가 아니라 여러분의 환경 설정에 있습니다 :PES5_Hmmmm:.

### `CS0122: inaccessible due to its protection level`

- **증상**: 잘 돌아가는 모드에서 복사한 코드가 컴파일되지 않습니다: `addStatusEffect`, `getHit`, `_localized_text`, `addBuilding`.
- **원인**: 그것들은 `internal`입니다. NML은 여러분의 `Code/*.cs`를 자체 **퍼블리사이즈된** 복사본(`StreamingAssets/Mods/NML/Assembly-CSharp-Publicized.dll`)에 대해 컴파일하므로, 일반 소스 모드에서는 그냥 됩니다. 이 오류는 Visual Studio에서, 그것들을 숨기는 원래의 `Assembly-CSharp.dll`에 대해 여러분만의 `.dll`을 빌드할 때 나타납니다.
- **해결책**: 프로젝트에서 그 퍼블리사이즈된 복사본을 참조하거나, 공개된 방법을 쓰세요:

| 대신 | 이걸 쓰세요 |
| --- | --- |
| `actor.addStatusEffect("x", 20f)` | `World.world.statuses.newStatus(actor, AssetManager.status.get("x"), 20f)` |
| `actor.getHit(5f, ...)` | `actor.changeHealth(-5)` |
| `LocalizedTextManager.instance._localized_text[k] = v` | `LM.Add("en", k, v)` 다음 `LM.ApplyLocale(false)` |

### 내 컴퓨터에선 잘 되는데 다른 컴퓨터에선 아무 반응 없음

- **증상**: 모드가 로드는 되는데 내용이 없다거나, 첫 줄에서 예외가 난다는 제보가 옵니다.
- **원인**: 거의 항상 이 넷 중 하나입니다: 여러분의 사용자 이름이 들어간 하드코딩된 경로; *폴더*가 아니라 모드의 *내용물*을 압축함; 릴리스 사이에 바뀐 `GUID`; 오래된 `.dll`과 함께 배포된 `Code/`.
- **해결책**: 경로는 `GetDeclaration().FolderPath`에서 만드세요. 폴더를 압축하세요. `GUID`는 한 번 정하면 절대 바꾸지 마세요. `Code/` **또는** `.dll` 중 하나만 배포하고, 둘 다는 절대 안 됩니다.

## 처음엔 작동하다가 나중에 고장남

천천히 터지는 것들. 어제까지 멀쩡하던 모드인데, 모드는 하나도 바뀌지 않았습니다 :PES2_Shrug:.

### 다른 모드가 내 콘텐츠를 자동으로 덮어씀

- **증상**: 특정 다른 모드를 켜면 여러분의 특성이 사라집니다. 로그에는 한참 전에 스크롤되어 지나간 한 줄: `duplicate asset - overwriting...`
- **원인**: ID 네임스페이스는 라이브러리마다 하나뿐이고, 바닐라와 모든 모드가 공유합니다. 마지막 등록이 이기고, 로드 순서는 여러분이 정할 수 없습니다.
- **해결책**: 모든 ID에 접두사를 붙이세요: `hello_swift`, 절대 `swift`가 아니라. `if (AssetManager.traits.has(SWIFT)) return;`으로 막으세요. 바닐라 콘텐츠를 *바꾸려면*, 대체품을 추가하는 대신 `get()`으로 가져와서 그 자리에서 수정하세요.

### 모드 로딩 중 `World.world`에서 크래시

- **증상**: 지도를 건드리는 첫 번째 줄에서 크래시가 납니다.
- **원인**: `OnModLoad`는 어떤 세계도 존재하기 전에 실행됩니다. 에셋 라이브러리는 준비되어 있지만, 세계는 아닙니다.
- **해결책**: 등록은 `OnModLoad`에서 하고, 세계는 `Update()`에서 `if (!Config.game_loaded) return;`와 `World.world`, `World.world.units`, `MapBox.instance`의 null 확인 뒤에서 건드리세요.

### 내 데이터가 엉뚱한 생명체를 제어함

- **증상**: 세이브를 불러오거나 새 세계를 만든 뒤, 상관없는 유닛들이 홀린 듯 행동합니다.
- **원인**: 유닛 ID는 **세계별**이며 처음부터 다시 발급됩니다. `Actor` 객체를 들고 있는 건 더 나쁩니다: 죽은 액터는 풀에 들어갔다가 되살아나므로, 여러분의 참조는 절대 null이 되지 않고, 지금은 다른 누군가입니다.
- **해결책**: 세계가 바뀐 걸 알아채고 전부 버리세요. 세계 시간이 거꾸로 가는 것이 가장 값싼 신호입니다:

```csharp
double now = World.world.getCurWorldTime();
if (_lastWorldTime >= 0.0 && now < _lastWorldTime - 1.0) MyRegister.Clear();
_lastWorldTime = now;
```

### 저장 후 불러오면 모든 것이 사라짐

- **증상**: 여러분의 유닛들이 바닐라 동작으로 돌아갔는데, 여전히 여러분의 특성은 달고 있습니다.
- **원인**: 직렬화되는 건 게임 자체의 데이터 클래스뿐이고, 여러분의 static 딕셔너리는 아닙니다. 특성은 ID로 저장되며, **로드 시점에 라이브러리에 없는 ID는 조용히 버려집니다**. 그래서 비활성화하고, 불러오고, 다시 활성화하면 모든 유닛에서 특성이 벗겨집니다.
- **해결책**: 살아남는 표시로 특성을 쓰고, 거기서 복원하세요: `trait.action_on_augmentation_load = (pActor, pTrait) => MyRegister.Restore(pActor);`
- **또는**: 상태를 유닛 자체에 보관하세요. 유닛의 커스텀 데이터 저장소는 유닛과 함께 저장됩니다: **[기억해 두기](#/nml/saving-data)** 참고.

### 유닛들이 무리지어 멈춤

- **증상**: 유닛 무리가 움직임을 멈추고, 그 무리가 매 프레임 바뀝니다. 예외는 프레임마다 하나이지, 수천 개가 아닙니다.
- **원인**: 유닛별 루프에는 try/catch가 없습니다. 유닛 *i*에서 예외가 나면 그 프레임에서는 그 뒤의 모든 유닛을 건너뜁니다.
- **해결책**: 모든 패치와 모든 커스텀 행동의 `execute` 본문을 try/catch로 감싸고, 실패하면 `BehResult.Stop`을 반환하세요.

### Harmony 패치의 절반이 적용되지 않음

- **원인**: `PatchAll`은 하나의 오류 발생 시 전체 작업을 중단합니다.
- **해결책**: 클래스 단위로 개별 패치를 적용하세요 (**[Harmony 패치](#/nml/harmony-patches)** 참조).

### 내 `updateStats` 패치가 다른 플레이어에게서 크래시

- **원인**: `updateStats`는 여러 스레드에서 병렬(Parallel)로 실행됩니다.
- **해결책**: 해당 메서드에서는 유닛의 로컬 값만 변경하고 전역 작업은 `Update()`에서 처리하세요.

### `getHit`을 패치했는데도 건물이 피해를 입음

- **원인**: `getHit`은 `Actor`와 `Building`에 각각 오버라이드되어 있습니다.
- **해결책**: 대상 구체 클래스에 각각 패치를 적용하세요.

### 내 Prefix가 다른 모드 3개를 고장냄

- **증상**: "당신 모드가 모드 X를 망가뜨렸어요." 로그엔 아무것도 없고, X의 제작자는 혼자서는 재현하지 못합니다.
- **원인**: `false`를 반환하면 원본 **그리고 여러분 다음에 오는 다른 모든 모드의 패치**를 건너뜁니다. `updateStats`에서는 오래된 캐시 플래그가 유닛에 영원히 남기도 합니다.
- **해결책**: Prefix로 취소하기보다 Postfix로 조정(`__result *= 0.5f`)하세요. 꼭 취소해야 한다면 가장 좁은 메서드를 취소하고, 신경 쓰지 않는 모든 경우에는 일찍 `return true`하세요.

### 유닛이 영원히 가만히 있거나 매 프레임 크래시

- **증상**: 태스크 이름이 없는 유닛 하나가 영원히 멈춰 있거나, 매 틱마다 스택 트레이스가 나옵니다.
- **원인**: 알 수 없는 **태스크** ID는 조용하고 영구적인 무동작이고, 알 수 없는 **잡** ID는 매 틱 크래시입니다.
- **해결책**: 로드할 때 ID를 한 번 검증하고, 태스크는 그것을 나열하는 잡보다 먼저 등록하고, 확인하지 않은 ID를 `next_job_delegate`에 절대 넘기지 마세요.

### 커스텀 AI가 원래 기본 AI로 돌아감

- **증상**: 시간이 좀 지나면, 여러분의 등록부에는 여전히 있는데 일부 유닛이 바닐라 AI로 돌아가 있습니다.
- **원인**: 액터는 풀링됩니다: "새" 유닛은 잡 델리게이트가 방금 초기화된 재활용 객체입니다. 전투도 그것을 초기화합니다.
- **해결책**: 한 번이 아니라, 여러분의 주기에 맞춰 계속 다시 설정하세요: `if (pActor.ai.next_job_delegate != MyAI.NextJob) pActor.ai.next_job_delegate = MyAI.NextJob;`

### 게임이 1초에 4번씩 끊김

- **증상**: 평균 FPS는 괜찮아 보이는데, 게임이 규칙적으로 끊기고, 특별히 무거운 함수는 하나도 없습니다.
- **원인**: 모든 것이 같은 틱에 생각하고, 유닛은 현재 행동이 끝날 때만 다음으로 넘어가므로, 다 같이 끝납니다.
- **해결책**: `execute` 안이 아니라 여러분의 타이머에서 생각하세요. 개체들을 나눠서 한 번에 한 조각씩 처리하세요. 목록은 미리 할당하고, LINQ, 람다, `Debug.Log`는 그 경로에서 빼세요.

### 창 뒤의 맵이 클릭됨

- **증상**: 플레이어가 패널의 컨트롤을 클릭했는데 그 아래에 유닛이 생성됩니다.
- **원인**: `GraphicRaycaster`가 없는 canvas는 그려지기는 하지만 클릭 판정이 되지 않습니다. 그리고 `unselect_when_window`는 게임 자체의 창만 알기 때문에, 직접 만든 패널은 활성 권능을 절대 해제하지 않습니다.
- **해결책**: `Canvas` + `overrideSorting` + `sortingOrder` + `GraphicRaycaster` + 배경 `Image`, 전부 함께. 라벨에는 `raycastTarget = false`. 창이 열리면 권능은 직접 해제하세요.

### 패널을 열 때마다 메모리 사용량이 증가함

- **증상**: 패널을 열 때마다 메모리가 계단식으로 늘고, 오래 플레이하면 느려집니다.
- **원인**: `Destroy(root)`는 GameObject 트리를 해제하지만, **여러분이** 만든 `Texture2D`나 `Sprite`는 아무도 수거하지 않는 별도의 객체입니다.
- **해결책**: 직접 만든 것은 파괴하고 참조를 null로 만드세요. `SpriteTextureLoader`에서 온 스프라이트는 파괴하지 **마세요**. 그것들은 공유됩니다.

### 새로운 기본 설정값이 기존 플레이어에게 적용되지 않음

- **증상**: `default_config.json`에서 기본값을 바꿨는데, 기존 플레이어는 예전 값을 그대로 가지고 있습니다. 새로 설치한 경우는 괜찮습니다.
- **원인**: 그 파일은 틀일 뿐입니다. 실제 값은 `mods_config\<UID>.config`에 있고, 여기에 **항목 전체**가 저장되므로 바꾼 범위나 이름을 바꾼 콜백도 가려집니다.
- **해결책**: 그 파일을 지운 상태로 테스트하세요. 기존 사용자를 위해 범위나 콜백을 바꿔야 한다면, 예전 항목을 수정하지 말고 새 `Id`를 추가하세요.

### 설정 슬라이더를 움직여도 콜백이 실행되지 않음

- **증상**: 그 줄은 작동하고 값도 저장되는데, 여러분의 메서드는 한 번도 호출되지 않습니다.
- **원인**: 콜백은 `Namespace.Type:MethodName`이고, 메서드는 **static**이어야 하며, 매개변수는 타입과 맞아야 합니다(`INT_SLIDER` → `int`, `SLIDER` → `float`, `SWITCH` → `bool`, `TEXT` → `string`).
- **해결책**: 네임스페이스를 포함하고, static으로 만들고, 타입을 맞추세요. 변경은 드래그하는 동안이 아니라 창을 **닫을 때** 적용됩니다.
