# Заглядываем внутрь игры :wbeyeball:

**UnityExplorer** - это внутриигровой инспектор. Он позволяет поставить игру на паузу на любом экране, кликнуть по любому окну, кнопке или юниту и в реальном времени прочитать каждое их значение.

Зачем он тебе: вместо того чтобы гадать на кофейной гуще, из чего собрано ванильное окно, ты просто открываешь его и *смотришь*. Любой вопрос формата "как они вообще это сделали?" решается ровно за две минуты.

## Как его установить

1. Сначала настрой **BepInEx**, см. **[Живая консоль](#/toolbox/bepinex-console)**.
2. Скачай [**UnityExplorer для BepInEx 5 (Mono)**](https://github.com/sinai-dev/UnityExplorer/releases) (забирай архив `UnityExplorer.BepInEx5.Mono.zip` со страницы релизов).
3. Распакуй zip в папку `C:\Program Files (x86)\Steam\steamapps\common\worldbox\BepInEx\plugins/`. Убедись, что и `UnityExplorer.BIE5.Mono.dll`, и сопутствующая зависимость `UniverseLib.Mono.dll` лежат внутри!
4. Запусти игру и нажми **F7** (клавиша открытия по умолчанию).

```text
worldbox/ (C:\Program Files (x86)\Steam\steamapps\common\worldbox\)
└── BepInEx/
    └── plugins/
        └── sinai-dev-UnityExplorer/ (or directly in plugins/)
            ├── UnityExplorer.BIE5.Mono.dll
            └── UniverseLib.Mono.dll
```

## Три панели, которыми ты реально будешь пользоваться

| Панель | Для чего она нужна |
| --- | --- |
| **Object Explorer → Scene Explorer** | Дерево объектов всего, что прямо сейчас есть на экране. Твое окно точно где-то тут |
| **Inspector** | Кликни по любому объекту в дереве и увидишь каждый компонент и каждое поле с их текущими значениями |
| **C# Console** | Введи строчку кода на C# и выполни ее прямо в запущенной игре. Никаких перезапусков |

## Пример 1: узнать, как устроено ванильное окно

Ты хочешь, чтобы твое окно выглядело в точности как родные окна игры. Делаем так:

1. В игре открой нужное окно (например, Законы мира (world law)).
2. Нажми F7, перейди в **Object Explorer → Scene Explorer** и раскрой `CanvasMain` → `canvas_ui`.
3. Кликай по дочерним объектам, пока подсвеченный элемент не совпадет с открытым окном.
4. В инспекторе изучи его компоненты: `Image` с 9-slice спрайтом, размеры в `RectTransform`, компонент `ScrollRect`.

Теперь ты знаешь размеры, путь к спрайту и точную структуру, которую можно скопировать на странице **[Пользовательские окна](#/nml/custom-windows)**. Именно так люди экономят три часа жизни, не подбирая якоря вслепую :PES5_Peek:.

## Пример 2: прочитать настоящие значения полей ассета

Открой **C# Console** и выполни:

```csharp UnityExplorer C# console
var t = AssetManager.traits.get("strong");
UnityExplorer.ExplorerCore.Log(t.path_icon);
UnityExplorer.ExplorerCore.Log(t.group_id);
```

В выводе лога UnityExplorer ты сразу же увидишь:

```text
[Message:UnityExplorer] ui/Icons/actor_traits/iconStrong
[Message:UnityExplorer] physique
[Message:UnityExplorer] Invoked REPL (no return value)
```

Ты только что вытащил путь к иконке и группу ванильной черты (trait) прямо из работающей игры. Скопируй их в свою черту, и она встанет в то же самое место интерфейса - причем с иконкой, которая реально существует.

## Пример 3: проверить идею до написания целого мода

Все в той же консоли C#:

```csharp UnityExplorer C# console
// спавним волка на тайле с координатами x=100, y=100
var tile = World.world.GetTile(100, 100);
World.world.units.spawnNewUnit("wolf", tile);
```

Если сработало здесь, сработает и в твоем моде. А если вылетел эксепшн, ты только что сэкономил себе целый цикл пересборки и перезапуска игры :aPES2_ThumbsUp:.

> [!TIP] Используй вместе с консолью
> UnityExplorer отвечает на вопрос "из чего это сделано?". Консоль BepInEx отвечает на вопрос "выполнился ли вообще мой код?". Практически любая проблема при создании модов сводится к одному из этих двух вопросов.
