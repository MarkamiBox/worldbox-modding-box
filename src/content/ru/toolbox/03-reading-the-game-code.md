# Читаем код игры :wbnerd:

Все ответы по созданию модов для WorldBox уже давно записаны: они находятся внутри самой игры :wbbru:. **dnSpy** (или **ILSpy**) превращает скомпилированный файл игры обратно в понятный C#, чтобы ты мог в точности узнать, как называется метод, какие аргументы он принимает и что именно делает.

Это главный и самый важный шаг от "бездумного копирования кусочков кода" к "настоящему моддингу" :3074-woah:.

## Открываем игру

1. Скачай [**dnSpy**](https://github.com/dnSpyEx/dnSpy/releases) (или [**ILSpy**](https://github.com/icsharpcode/ILSpy/releases) - суть та же, просто другие кнопки).
2. Открой следующий файл:

```text
worldbox/worldbox_Data/Managed/Assembly-CSharp.dll
```

Этот единственный файл и есть весь код игры. Слева откроется дерево всех классов: `Actor`, `AssetManager`, `GodPower`, `ScrollWindow` и всех остальных без исключения.

## Четыре вещи, которые ты будешь делать постоянно

### 1. Найти нужный класс

`Ctrl+Shift+K` ищет типы. Введите `ActorTrait`, откройте его, и вы увидите каждое поле, которое можно задать, с его типом и значением по умолчанию:

```csharp Assembly-CSharp / ActorTrait
public string path_icon;
public string group_id;
public int rate_birth;
public bool can_be_cured;
```

Этот список *и есть* документация к странице **[Свои черты](#/nml/custom-traits)**. Читайте и **типы**: `rate_birth` - это `int`, так что `rate_birth = 0.5f` не скомпилируется. Тот же трюк для `ItemAsset`, `BuildingAsset`, `StatusAsset`, для чего угодно.

### 2. Проверить реальную сигнатуру метода

Угадывать имена методов наугад - верный способ убить час на поиски ошибки компиляции. Лучше просто посмотреть. Поиск `addTrait` в классе `Actor` покажет:

```csharp Assembly-CSharp / Actor
public bool addTrait(string pTraitID, bool pRemoveOpposites = false)
public bool hasTrait(string pTraitID)
public void removeTrait(string pTraitID)
```

Теперь ты точно знаешь: метод принимает строку, возвращает булево значение и имеет второй необязательный аргумент.

### 3. Подсмотреть, как это сделано в самой игре

Самая полезная фишка. Хочешь сделать работающий закон мира (world law)? Найди `WorldLawLibrary`, открой метод `init()` и прочитай, что написали сами разработчики:

```csharp Assembly-CSharp / WorldLawLibrary.init()
world_law_mutant_box = add(new WorldLawAsset
{
    id = "world_law_mutant_box",
    group_id = "units",
    icon_path = "ui/Icons/worldrules/icon_mutant_box",
    default_state = false
});
```

Скопируй эту структуру, замени id и иконку - и твой закон готов. Каждый метод `*Library.init()` в игре - это готовый бесплатный туториал по конкретному типу ассета.

### 4. Найти все существующие ID

Идентификаторы - это обычные строки, и при ошибке игра просто молча ничего не сделает. Все они живут в методах `init()`: в `TileLibrary.init()` лежат все ID тайлов, в `ItemLibrary.init()` - все оружие, в `ActorAssetLibrary.init()` - все существа.

## public, internal и ты

При чтении кода ты будешь встречать три модификатора перед методами:

| Слово | Что это значит для тебя |
| --- | --- |
| `public` | Можно вызывать. Всегда. |
| `internal` | Можно вызвать, только если проект собирается с **publicized** копией `Assembly-CSharp.dll` |
| `private` | Напрямую вызвать нельзя. Найди публичный метод, который его вызывает, или пропатчи (см. **[Патчи Harmony](#/nml/harmony-patches)**) |

"Publicized" DLL - это копия библиотеки (library), в которой все члены сделаны публичными. Большинство авторов модов WorldBox используют именно ее, и поэтому код вроде `actor.getHit(...)` у них компилируется, а у тебя нет. Если что-то упорно отказывается собираться, а dnSpy пишет `internal`, причина именно в этом.

> [!TIP] Держи его открытым во время работы
> Никто не требует "читать весь код игры запоем", так никто не делает. Держи декомпилятор рядом с редактором кода и подсматривай имена прямо по ходу дела. Две секунды в поиске сэкономят тебе двадцать минут бессильной злости над непонятной ошибкой компилятора :PES_ThumbsUp:.

Когда тебе нужно узнать только имя метода и его сигнатуру, быстрее воспользоваться **[Поиском методов](#/tools/methods)** прямо на этом сайте: каждый метод в игре с удобным поиском и сразу помеченными `internal`. А к dnSpy возвращайся тогда, когда нужно увидеть, что метод делает *на самом деле*: этого никакой справочник тебе не заменит.
