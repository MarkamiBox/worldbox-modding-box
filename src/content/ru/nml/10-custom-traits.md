# Пользовательские черты :wbstrongminded:

Черта (trait) — это постоянная метка на существе: *храбрый*, *быстрый*, *бессмертный*. Она отображается в окне персонажа, может изменять его характеристики (stats), выполнять код при атаке, получении удара или гибели существа, а также передаваться по наследству детям.

Кроме того, это самая простая в реализации вещь во всей игре, поэтому с черт почти всегда начинается знакомство с моддингом. Мой - нет: мой первый мод был обёрткой вокруг чужого мода, что само по себе своего рода жульничество :trollface:.

## Всегда добавляйте префикс к своим ID

Каждый ассет в WorldBox хранится в едином плоском списке по ключу `id`. Если вы зарегистрируете `fast`, а другой мод тоже зарегистрирует `fast`, то второй **перезапишет** первый, а в логе появится неприметная строчка, которую никто не заметит.

Поэтому: `hello_swift`, а не `swift`. Короткое имя мода, знак подчёркивания, название элемента. Делайте так для черт, предметов (item), построек, сил бога, статусов (status) — вообще для всего :aPES4_Noted:.

## Регистрация черты

```csharp Mods/HelloBox/Code/HelloTraits.cs
namespace HelloBox
{
    public static class HelloTraits
    {
        // Идентификатор, записанный один раз. Все остальные файлы ссылаются на HelloTraits.SWIFT,
        // благодаря чему опечатка станет ошибкой компиляции, а не чертой, которая молча не работает.
        public const string SWIFT = "hello_swift";

        public static void Initialize()
        {
            // Никогда не регистрируйте один и тот же ID дважды. Библиотека залогирует ошибку и перезапишет ассет.
            if (AssetManager.traits.has(SWIFT)) return;

            ActorTrait swift = new ActorTrait
            {
                id = SWIFT,
                needs_to_be_explored = false,   // already discovered, no exploring needed
                path_icon = "ui/Icons/iconSpeed",   // ванильная иконка, позже замените на свою
                group_id = "physique",              // в какой вкладке книги черт она появится
                rate_birth = 0,                     // 0 = никогда не появляется случайно при рождении
                can_be_given = true,                // игрок может выдать её в редакторе
                can_be_removed = true,
                can_be_cured = false
            };

            // add() регистрирует черту И выделяет блок характеристик. Именно в таком порядке.
            AssetManager.traits.add(swift);

            swift.base_stats["speed"] = 20f;
            swift.base_stats["attack_speed"] = 10f;
            swift.base_stats["damage"] = 5;
        }
    }
}
```

И одна строчка в `Main.cs`:

```csharp Mods/HelloBox/Code/Main.cs
protected override void OnModLoad()
{
    LogInfo("HelloBox is alive!");
    HelloTraits.Initialize();
}
```

### Назначение каждого поля

- **`AssetManager.traits`**: Библиотека (library), хранящая все черты существ в игре (и ванильные, и модифицированные). `has`, `get`, `add` и `clone` — четыре метода, с которыми вы будете работать в каждой библиотеке на всех последующих страницах.
- **`path_icon`**: Маленькое изображение в окне персонажа. Это *путь*, а не имя файла. См. **[Спрайты и ресурсы](#/nml/sprites-and-resources)**. Игра заполняет это поле автоматически только при создании собственных библиотек (что происходит до загрузки модов), поэтому для вашей черты оно останется пустым, если не указать его явно.
- **`needs_to_be_explored`**: по умолчанию `true`, то есть черта заблокирована в книге (book) знаний, пока игрок не найдёт её в мире. `false` делает её доступной с первой секунды. HelloBox ставит это на всё, чтобы вы видели, что сделали, не разыскивая.
- **`group_id`**: В какой вкладке книги черт она отображается. Полный список приведен ниже.
- **`rate_birth`**: Шанс естественного получения новорождённым. `0` означает «только если что-то выдаст её принудительно».
- **`can_be_given` / `can_be_removed`**: Может ли игрок выдавать или снимать её в редакторе черт. По умолчанию оба равны `true`; установите в `false` для черт, которые должны быть неснимаемыми или выдаваться только вашим кодом.
- **`base_stats[...]`**: Бонусы к характеристикам. Полный перечень параметров можно найти на странице **[Справочник характеристик](#/nml/stats)**.

> [!WARNING] Характеристики задаются **строго после** `add()`
> У только что созданного через `new` объекта `ActorTrait` блока характеристик ещё нет. Библиотека выделяет его внутри вызова `add()`. Обратитесь к `base_stats` раньше этой строки — и столкнётесь с самой частой ошибкой моддинга WorldBox:
> `NullReferenceException: Object reference not set to an instance of an object`
>
> Это же правило касается статусов, предметов, построек и существ. Исключение составляет метод `clone()`, который уже вызывает `add()` за вас.

> [!TIP] Такой же переключатель есть почти у всего, что вы делаете
> `needs_to_be_explored` живёт в базовом классе всех открываемых ассетов, поэтому работает для актёров, всех семи видов черт, предметов, модификаторов (modifier) и законов мира (world law). У сил бога, статусов, зданий (building), дропов, облаков (cloud), тайлов и снарядов (projectile) этапа открытия нет вовсе :wbsmirk:.

### Ванильные группы черт

`group_id` обязан быть существующей категорией, иначе ваша черта не появится нигде:

`cognitive` · `mind` · `spirit` · `physique` · `health` · `body` · `appearance` · `protection` · `skills` · `merits` · `acquired` · `fun` · `fate` · `miscellaneous` · `special`

Хотите создать собственную вкладку? См. **[Группы черт и вкладки](#/nml/trait-groups)**.

## Тексты и локализация

Без файлов локализации черта будет отображаться в игре как сырой ключ `trait_hello_swift`, и выглядит это ровно так профессионально, как звучит :pepeclown:. Создайте `Locales/ru.json`:

```json Mods/HelloBox/Locales/en.json
{
  "trait_hello_swift": "Swift",
  "trait_hello_swift_info": "Moves like the world owes it money."
}
```

Ключ — это **не** просто ID черты. Каждый тип черты добавляет собственный префикс:

| Тип черты | Ключ названия | Ключ описания |
| --- | --- | --- |
| Actor trait | `trait_<id>` | `trait_<id>_info` |
| Culture trait | `culture_trait_<id>` | `culture_trait_<id>_info` |
| Religion trait | `religion_trait_<id>` | `religion_trait_<id>_info` |
| Subspecies trait | `subspecies_trait_<id>` | `subspecies_trait_<id>_info` |
| Clan trait | `clan_trait_<id>` | `clan_trait_<id>_info` |
| Language trait | `language_trait_<id>` | `language_trait_<id>_info` |
| Kingdom trait | `kingdom_trait_<id>` | `kingdom_trait_<id>_info` |

Существует также вторая строчка описания, `<prefix>_<id>_info_2`, для черт, которым требуется расширенное пояснение.

## Собственная иконка

`path_icon` — это путь к файлу внутри папки `GameResources/` вашего мода. Расширение в строке указывать не нужно.

```text Mods/HelloBox/
HelloBox/
└── GameResources/
    └── ui/Icons/
        └── iconHelloSwift.png
```

```csharp
swift.path_icon = "ui/Icons/iconHelloSwift";
```

Иконки черт небольшие и отображаются с разрешением примерно 32x32. При желании вы можете положить PNG в свою подпапку: путь `ui/Icons/hellobox/iconSwift` сработает точно так же, главное чтобы он совпадал со строкой.

Остальные шесть систем черт имеют собственные ванильные папки (`ui/Icons/culture_traits/`, `religion_traits/`, `clan_traits/` и т.д.). Использовать именно их не обязательно, но соседство с копируемыми ассетами упростит поиск ресурсов (resource) в будущем. Полная таблица доступна в **[Спрайты и ресурсы](#/nml/sprites-and-resources)**.

## Как заставить черту *действовать*

Характеристики статичны. Однако черта также может выполнять ваш код в четыре ключевых момента:

```csharp
// каждые несколько секунд, пока существо живо
swift.special_effect_interval = 3f;
swift.action_special_effect = (BaseSimObject pSelf, WorldTile pTile) =>
{
    Actor actor = pSelf as Actor;
    if (actor == null || !actor.isAlive()) return false;

    actor.restoreStamina(5);
    return true;
};

// в момент гибели существа
swift.action_death = (BaseSimObject pSelf, WorldTile pTile) => { return true; };

// при получении удара
swift.action_get_hit = (BaseSimObject pSelf, BaseSimObject pAttacker, WorldTile pTile) => { return true; };

// каждый раз, когда одна из атак существа попадает, сразу после урона
swift.action_attack_target = (BaseSimObject pSelf, BaseSimObject pTarget, WorldTile pTile) =>
{
    Actor self = pSelf as Actor;
    // pTarget может быть зданием, и удар мог его только что уничтожить
    if (self == null || !self.isAlive() || pTarget == null) return false;

    self.restoreHealth(2);
    return true;
};
```

Два золотых правила: **всегда проверяйте существо на null и на то, что оно живо**, и возвращайте `false`, если никаких действий совершено не было. Эти функции выполняются для каждого обладателя черты на карте, непрерывно.

> [!NOTE] `action_birth` и `action_growth` существуют, но здесь никогда не срабатывают
> `ActorTrait` наследует оба поля, поэтому они компилируются. Игра читает их только у черт **подвида (subspecies)**: она объединяет черты подвида в один общий колбэк рождения и один колбэк взросления и вызывает именно их. На черте существа они просто лежат мёртвым грузом, без единой ошибки :wbreally:. Если вам нужно "при рождении юнита", сделайте черту подвида: **[Черты подвидов](#/nml/subspecies-traits)**.

### Когда черта получена, потеряна или загружена

Ещё три хука выполняются один раз, а не постоянно. Они принимают другой делегат, `WorldActionTrait`, который передаёт вам владельца как `NanoObject` и саму черту:

```csharp
// один раз, в момент, когда addTrait() ставит её на юнита
swift.action_on_augmentation_add = (NanoObject pTarget, BaseAugmentationAsset pTrait) =>
{
    Actor actor = pTarget as Actor;
    if (actor == null || !actor.isAlive()) return false;

    actor.restoreHealth(actor.getMaxHealth());   // приветственный подарок, один раз
    return true;
};
```

| Поле | Когда срабатывает |
| --- | --- |
| `action_on_augmentation_add` | `addTrait()` успешно сработал |
| `action_on_augmentation_remove` | `removeTrait()` её снял, в том числе когда другая черта вытолкнула её как противоположность или через `traits_to_remove` |
| `action_on_augmentation_load` | Загрузился сохранённый мир, и юнит вернулся с этой чертой |

Загруженный юнит получает свои черты обратно **без** прохода через `addTrait()`, так что `_add` не срабатывает повторно. Если `_add` что-то настраивает, что не сохраняется в файле сохранения, повторите это в `_load`.

## Противоположности и исключения

Ванильный способ - это `addOpposite("slow")` и `traits_to_remove_ids`. Оба пишут только **id**, а игра превращает эти id в наборы, которые реально читает, один раз, во время загрузки, ещё до появления вашего мода. На вашей черте они не делают ничего :wbfacepalm:. Заполните итоговые поля сами, после `add()`:

```csharp
ActorTrait slow = AssetManager.traits.get("slow");
if (slow != null)
{
    // addTrait() проверяет только собственный набор НОВОЙ черты, поэтому заполните обе стороны:
    // иначе медленный юнит откажется от swift, а быстрый юнит спокойно станет медленным
    swift.opposite_traits = new HashSet<ActorTrait> { slow };
    if (slow.opposite_traits == null) slow.opposite_traits = new HashSet<ActorTrait>();
    slow.opposite_traits.Add(swift);
}

// получение swift снимает эти; игра читает массив, а не id
ActorTrait fat = AssetManager.traits.get("fat");
if (fat != null) swift.traits_to_remove = new ActorTrait[] { fat };
```

`HashSet` требует `using System.Collections.Generic;` в начале файла.

> [!WARNING] `opposite_trait_mod` требует `opposite_traits`
> `opposite_trait_mod` меняет, насколько сильно два юнита симпатизируют друг другу, когда у одного есть противоположность черты другого. Код социальных отношений проходит по `opposite_traits` без проверки на null, так что установка модификатора при оставленном `null` наборе бросит `NullReferenceException` при первой же оценке двух юнитов друг другом. Дайте набору значение, пусть даже пустое.

## Редкость

`rarity` решает цвет имени и строку редкости в подсказке черты, а `Rarity.R3_Legendary` также получает особую легендарную рамку. Значения: `R0_Normal`, `R1_Rare`, `R2_Epic` и `R3_Legendary`.

Для ванильных черт это в основном автоматика: пока игра загружается, библиотека считает, что делает каждая черта (действия, решения, заклинания, боевые действия, теги), и повышает всё, что что-то делает, до `R1_Rare` или `R2_Epic`. Ваша черта появляется после этого прохода, так что сохраняет то, что вы написали, а если вы ничего не написали - это значение по умолчанию, `R1_Rare`, сколько бы она ни делала. Установите его сами:

```csharp
swift.rarity = Rarity.R2_Epic;
```

## Разблокировка из кода

При `needs_to_be_explored = true` черта стартует заблокированной в книге знаний. `unlock()` - это то, как игра её открывает:

```csharp
AssetManager.traits.get(HelloTraits.SWIFT)?.unlock();
```

Это добавляет id в прогресс игрока, показывает подсказку "новое знание" и сохраняет файл прогресса. `unlock(false)` пропускает сохранение: используйте это, когда открываете несколько вещей подряд, а затем вызовите `GameProgress.saveData()` один раз в конце. Метод возвращает `false` и ничего не делает, если черта уже доступна, а черта с `needs_to_be_explored = false` доступна всегда. Вызывайте его из игрового процесса, когда игрок это заслужил: это его настоящий файл прогресса, и черта останется разблокированной в каждом следующем мире.

`unlocked_with_achievement` по умолчанию уже равен `false`. Запись `unlocked_with_achievement = false` ничего не меняет.

## Выдача черты юниту

```csharp
actor.addTrait(HelloTraits.SWIFT);

if (actor.hasTrait(HelloTraits.SWIFT))
{
    // ...
}
```

> [!WARNING] `spawn_random_trait_allowed` читается один раз, при запуске
> Новые юниты получают стартовые черты из пула, который `BaseTraitLibrary.linkAssets()` собирает во время загрузки игры, ещё до появления вашего мода. Сам по себе флаг на вашей черте ничего не меняет: вашей черты нет в этом пуле, и случайно она не выпадет никогда. Добавьте её сами, с тем же весом, что и в ванили:
>
> ```csharp
> swift.spawn_random_trait_allowed = true;
> AssetManager.traits._pot_allowed_to_be_given_randomly.AddTimes(swift.spawn_random_rate, swift);
> ```
>
> `_pot_allowed_to_be_given_randomly` помечен как `protected`, поэтому это компилируется против публицированной сборки, с которой NML и так собирает ваш мод. `spawn_random_rate` по умолчанию равен `5`: увеличьте его, и черта будет выпадать чаще.

## Проверка работоспособности

Запустите игру, откройте окно любого существа, зайдите в редактор черт и загляните во вкладку `physique`. Черты там нет? В логе написано, почему так произошло, и ответ почти всегда кроется в одной из трёх причин: `can_be_given` равен false, `group_id` не существует, либо `path_icon` указывает в никуда :wbreally:.

## Остальные шесть разновидностей черт

Черты существ — лишь одна из **семи** систем черт в игре. У каждой из них своя библиотека, свои категории и свои сущности-владельцы, и все они устроены абсолютно так же, как описано на этой странице. Меняются только имя класса, библиотека и префикс ключа локализации.

| Система | Кому принадлежит | Страница |
| --- | --- | --- |
| Actor | одному существу | эта страница |
| Culture | культуре (culture) (разделяется её городами) | **[Черты культуры](#/nml/culture-traits)** |
| Religion | религии (religion) и её последователям | **[Черты религии](#/nml/religion-traits)** |
| Subspecies | ветви вида (подвиду (subspecies)) | **[Черты подвидов](#/nml/subspecies-traits)** |
| Clan | кровной династии | **[Черты кланов](#/nml/clan-traits)** |
| Language | языку и всем его носителям | **[Черты языков](#/nml/language-traits)** |
| Kingdom | государственной политике королевства (kingdom) | **[Черты королевств](#/nml/kingdom-traits)** |

Определитесь с владельцем до того, как начнёте писать черту. «Эльфы метко стреляют» — это черта культуры, если она должна распространяться вместе с городами, черта подвида, если она должна передаваться при размножении, и черта существа, если она является личным навыком конкретного воина. Ошибка в этом выборе — это разница между модом, преображающим мир за час, и модом, который не делает ровным счётом ничего :PES_ThinkAboutIt:.
