# Справочник характеристик :wbstonks:

Почти каждый ассет, который вы регистрируете, содержит блок `base_stats`, и почти каждая страница после этой что-то в него пишет. Ниже приведён полный список того, что туда разрешено помещать. Всё остальное - это краш, который ждёт своего часа :PES5_Hmmmm:.

## Как работает base_stats

`base_stats` — это словарь из `string` в `float`. Ключом обязан быть один из приведённых ниже идентификаторов. Передать неизвестный ключ **далеко не безобидно**: сеттер ищет ID в `base_stats_library`, получает `null` и немедленно бросает `NullReferenceException` прямо в вашем методе `Initialize()`.

Так что опечатка в имени характеристики не проходит тихо. Она роняет всю стадию регистрации ассетов, и всё, что написано после этой строчки, никогда не запустится. Храните имена характеристик в полях `const string`, если используете их более чем в одном месте.

```csharp
trait.base_stats["damage"] = 15;
trait.base_stats["multiplier_health"] = 0.25f;   // +25%, а не x0.25
```

## Откуда берутся показатели юнита

`Actor.updateStats()` очищает блок характеристик существа и собирает его заново с нуля в строго определённом порядке. Я до сих пор каждый раз заглядываю в эту таблицу:

| # | Источник | Примечание |
| --- | --- | --- |
| 1 | **Подвид**, плюс его мужской или женский блок | Если существо принадлежит к подвиду |
| 1b | **Actor asset** | Только если подвида **нет**. Подвид *замещает* ассет существа, а не накладывается сверху |
| 2 | **Клан**, плюс его мужской или женский блок | |
| 3 | **Язык** | |
| 4 | **Культура** | |
| 5 | Атрибуты лидера из личных данных существа | `diplomacy`, `stewardship`, `intelligence`, `warfare` |
| 6 | Каждый активный **эффект статуса** | |
| 7 | Предмет **дефолтной атаки** | Только когда существо безоружно |
| 8 | Каждая **черта существа (actor trait)** | Черты эпох пропускаются, если соответствующая эпоха не активна |
| 9 | Его **личность** | |
| 10 | Каждый **экипированный предмет** со своими модификаторами | |

Две частые ошибки:

- **Подвид заменяет характеристики ассета существа.** Задайте параметры для `human`, и существо с подвидом их никогда не увидит.
- **Религии в этом списке нет.** Блок `base_stats` черты религии никогда не доходит до существа. См. **[Черты религии](#/nml/religion-traits)**.

Ещё два следствия:

- Фиксированное значение вроде `damage` — это **бонус**, а не итоговое число. `damage = 15` на черте означает «+15 поверх всего остального».
- Характеристика вида `multiplier_*` — это **дробная прибавка к 1.0**. `multiplier_health = 0.5` означает +50%. `multiplier_health = -0.5` уменьшает здоровье вдвое.

> [!WARNING] `base_stats` не существует до регистрации ассета
> У ассета, созданного вручную через `new`, блок характеристик выделяется внутри вызова `add()`. Обратитесь к `base_stats` до этой строки — и получите `NullReferenceException`. Метод `clone()` вызывает `add()` за вас, поэтому после клонирования блок уже готов. Это самый частый краш во всём моддинге WorldBox.

## Combat

`damage` и `armor` делают почти всю работу. Остальное нужно, когда вы хотите, чтобы черта ощущалась иначе, а не просто сильнее.

| Характеристика | Что делает |
| --- | --- |
| `damage` | Фиксированный урон за удар |
| `damage_range` | Случайный разброс урона, прибавляемый к `damage` |
| `attack_speed` | Скорость нанесения ударов |
| `accuracy` | Шанс попадания |
| `critical_chance` | Шанс критического удара |
| `critical_damage_multiplier` | Множитель критического урона |
| `armor` | Фиксированное поглощение урона |
| `range` | Дистанция атаки |
| `throwing_range` | Дистанция для метательного оружия |
| `targets` | Сколько целей может задеть одна атака |
| `projectiles` | Сколько снарядов вылетает одновременно |
| `knockback` | Сила отбрасывания цели |
| `recoil` | Сила отдачи, отбрасывающая *атакующего* |
| `skill_combat` | Навык ближнего боя |
| `skill_spell` | Навык сотворения заклинаний |
| `status_chance` | Шанс наложить привязанный эффект статуса |
| `area_of_effect` | Радиус урона по площади |

## Multipliers

Все они представляют собой доли, прибавляемые к 1.0; `0.25` означает +25%.

## base_stats против base_stats_meta

Каждая черта несёт в себе **два** блока характеристик, и путаница между ними — самая частая ошибка баланса в модах на мета-черты:

| Блок | Куда попадает |
| --- | --- |
| `base_stats` | Вливается в владельца, а оттуда — в **каждое существо**, принадлежащее ему |
| `base_stats_meta` | Остаётся на самом владельце. Считывается культурой, кланом или подвидом, но никогда существом |

```csharp
trait.base_stats["damage"] = 5;             // каждый представитель этой культуры бьёт сильнее (включая фермеров)
trait.base_stats_meta["construction_speed"] = 10;   // группа строит быстрее. Урон отдельных жителей не меняется
```

Если бонус должен действовать только на часть членов группы (только воины, только взрослые), ни один из этих блоков вам не поможет. Используйте Postfix в Harmony на `Actor.updateStats` и фильтруйте условия самостоятельно. См. **[Патчи Harmony](#/nml/harmony-patches)**.

## Теги: характеристики без чисел

Блок `base_stats` также содержит набор **тегов (tags)** — логических флагов без числовых значений. Они объединяются по тем же правилам, что и характеристики, позволяя черте наделить существо иммунитетом к огню точно так же, как она даёт дополнительный урон:

```csharp
trait.base_stats.addTag("immunity_fire");
trait.base_stats.addTag("fast_swimming");

if (actor.stats.hasTag("immunity_fire")) { }
```

Теги, которые считывает сама игра:

| Группа | Теги |
| --- | --- |
| Иммунитет | `immunity_fire` · `immunity_cold` · `building_immunity_fire` · `damaged_by_water` |
| Перемещение | `fast_swimming` · `water_creature` · `immovable` · `walk_adaptation_sand` · `walk_adaptation_snow` · `walk_adaptation_swamp` |
| Разум | `strong_mind` · `has_sapience` · `has_emotions` · `has_advanced_memory` · `has_advanced_communication` · `can_read_any_book` · `mad` · `moody` · `unconscious` · `frozen_ai` |
| Поведение | `ignore_fights` · `love_peace` · `steal_items` · `needs_food` · `needs_mate` · `always_idle_animation` · `stop_idle_animation` · `generate_light` |
| Рацион | `diet_meat` · `diet_meat_insect` · `diet_fish` · `diet_blood` · `diet_grass` · `diet_crops` · `diet_fruits` · `diet_flowers` · `diet_nectar` · `diet_algae` · `diet_vegetation` · `diet_wood` · `diet_minerals` · `diet_tiles` · `diet_same_species` |
| Размножение | `reproduction_sexual` · `reproduction_asexual` · `oviparity` · `viviparity` |
| Природа | `civ` · `human` · `elf` · `orc` · `dwarf` · `demon` · `undead` · `magic` · `good` · `evil` · `neutral` · `nature_creature` · `neutral_animals` · `everyone` · `small` · `sliceable` |
| Строительство | `can_build_in_biome_corruption` · `can_build_in_biome_desert` · `can_build_in_biome_infernal` · `can_build_in_biome_permafrost` · `can_build_in_biome_swamp` · `can_build_in_biome_wasteland` |

В отличие от названия характеристики, неизвестный тег совершенно безвреден: он просто ни с чем не совпадёт. Но это также означает, что опечатка останется незамеченной, поэтому копируйте названия в точности. Выбирайте яд по вкусу :wbbre:.

## Чтение текущих значений юнита

`base_stats` — это *рецепт*. Свойство `stats` у живого `Actor` — это *готовый результат* после сложения всех параметров:

```csharp
float finalDamage = actor.stats["damage"];
```

Именно его вы при необходимости корректируете в Harmony Postfix на методе `Actor.updateStats` — см. **[Патчи Harmony](#/nml/harmony-patches)**.

## Добавление собственной характеристики

Вы можете зарегистрировать новый `BaseStatAsset` в `AssetManager.base_stats_library`. Он будет отображаться в инспекторе и суммироваться вместе со всеми. Чего он **не** будет делать — так это влиять на что-либо в игре: ванильный код не считывает характеристики, о которых не знает. Пользовательская характеристика полезна только как числовая ячейка, которую вы затем сами прочитаете в собственном Harmony-патче или ИИ-поведении.

В большинстве случаев правильный ответ — «используйте уже существующую характеристику», а второй по частоте — «заведите собственный словарь». Третьего я пока не нашёл.
