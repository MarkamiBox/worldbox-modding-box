# Логи и отладка :wbdebugburger:

Лог - единственная вещь в моддинге, которая всегда говорит вам чистую правду. Он отвечает на главный вопрос, который вы будете задавать себе тысячу раз: **мой код вообще выполнился?**

## Вывод строки в лог

Есть два способа, и оба приводят к записи в один и тот же файл.

```csharp Mods/HelloBox/Code/Main.cs
using NeoModLoader.api;
using UnityEngine;

namespace HelloBox
{
    public class Main : BasicMod<Main>
    {
        protected override void OnModLoad()
        {
            LogInfo("HelloBox is alive!");      // NML: сам автоматически подставит имя вашего мода в начало
            LogWarning("something smells");
            LogError("something exploded");

            Debug.Log("[HelloBox] plain Unity");  // Unity: префикс нужно писать вручную
        }
    }
}
```

Не используете `BasicMod`? В `NeoModLoader.services.LogService` есть точно такие же методы `LogInfo`, `LogWarning`, `LogError`, а также `LogStackTraceAsError` для вывода полного стека вызовов.

## Как выглядит здоровый лог

Запустите игру с вышеуказанным модом и найдите `HelloBox` в файле `Player.log`. Вы должны увидеть примерно следующее:

```text Player.log
005: Compile Mod HelloBox                = 2,2480
006: Load Resources From Mod HelloBox    = 0,0012
[NML]: [HelloBox]: OnLoad
[NML]: [HelloBox]: HelloBox is alive!
[NML]: [HelloBox]: Loaded
008: Init Mod HelloBox                   = 0,0014
```

Строка за строкой: NML скомпилировал файлы в `Code/`, загрузил ваши ресурсы, а затем вызвал `OnModLoad`, который и вывел вашу строку. Пронумерованные строки - это замеры времени каждого этапа в NML: число после `=` означает секунды, и некоторые из них подсвечиваются красным. **Красный цвет здесь не означает ошибку**, он лишь указывает на то, что данный шаг выполнялся дольше остальных :hmm:.

Главная строка - ваша собственная. Если строчки `[HelloBox]: HelloBox is alive!` нет, читайте дальше.

## Когда ваш код не компилируется

Прежде чем ваш мод сможет запуститься, NML должен его скомпилировать. Опечатка остановит сборку на месте и точно укажет причину:

```text Player.log
[NML]: Code\Main.cs(9,42): error CS1002: ; expected
[NML]: Failed to compile mod HelloBox
```

Читайте справа налево: **`; expected`** - это суть проблемы (пропущена точка с запятой), **`(9,42)`** - строка 9, символ 42, а **`Code\Main.cs`** - файл. Откройте его, перейдите на эту строку и поставьте точку с запятой.

Полезная информация находится на **первой** строке. Запись `Failed to compile mod HelloBox` снизу - это просто общий итог. Многие читают только её, пугаются и упускают готовый ответ, находящийся прямо над ней :PES4_1IQ:.

## Как выглядит лог с ошибками

Когда код скомпилировался, вы очень часто будете видеть другую картину :PES2_F::

```text Player.log
[NML]: [HelloBox]: HelloBox is alive!
NullReferenceException: Object reference not set to an instance of an object
  at HelloBox.HelloTraits.Initialize () [0x00021] in HelloTraits.cs:24
  at HelloBox.Main.OnModLoad () [0x0000c] in Main.cs:12
```

Выглядит пугающе, но на самом деле это простое предложение:

- **`NullReferenceException`**: вы обратились к объекту, который был пуст (`null`). 95% всех ошибок, с которыми вы столкнетесь.
- **`at HelloBox.HelloTraits.Initialize ()`**: метод, в котором это произошло.
- **`in HelloTraits.cs:24`**: **строка 24 вашего файла**. Посмотрите на неё: что-то в ней равно `null`.
- Строки ниже показывают стек вызовов от новых к старым. Обращайте внимание на файлы вашего мода.

Классическая причина именно такой ошибки: попытка изменить `base_stats` у ассета до его добавления в библиотеку. Подробности на странице **[Кастомные черты](#/nml/custom-traits)**.

## Где лежат логи

| Файл | Путь | Что это такое |
| --- | --- | --- |
| `Player.log` | `%USERPROFILE%\AppData\LocalLow\mkarpenko\WorldBox/` | Текущий сеанс игры |
| `Player-prev.log` | та же папка | **Предыдущий** сеанс - тот самый, который только что вылетел :aPES_Flatline: |
| `logs/error_*.log` | та же папка, внутри `logs/` | Отдельный файл на каждую перехваченную игрой ошибку |
| `mods_config/<GUID>.config` | та же папка | Сохраненные настройки вашего мода |

Вставьте `%USERPROFILE%\AppData\LocalLow\mkarpenko\WorldBox` в адресную строку Проводника Windows, чтобы попасть туда мгновенно.

## Живая консоль вместо лог-файла

Читать файл после закрытия игры - медленно. С **BepInEx** вы получаете черное окно консоли, в котором логи выводятся прямо во время игры: вы видите строку в тот же миг, когда нажимаете на кнопку. Настройка занимает две минуты: **[Консоль BepInEx](#/toolbox/bepinex-console)**.

Хотите кликать по игровым окнам и проверять свойства объектов в реальном времени? Для этого есть **[UnityExplorer](#/toolbox/unity-explorer)**.

## Не позволяйте одной ошибке убить весь мод

`OnModLoad` выполняется сверху вниз. Если строка 3 падает с ошибкой, строки с 4 по 20 вообще не выполнятся, и половина вашего мода молча не загрузится. Дайте каждой части свою страховку:

```csharp Mods/HelloBox/Code/Main.cs
protected override void OnModLoad()
{
    Stage("traits", HelloTraits.Initialize);
    Stage("items", HelloItems.Initialize);
    Stage("powers", HelloPowers.Initialize);
    LogInfo("HelloBox ready");
}

// Запускает один шаг, а в случае сбоя логирует его имя и продолжает работу дальше.
private static void Stage(string pName, System.Action pAction)
{
    try { pAction(); }
    catch (System.Exception e) { LogError($"stage '{pName}' failed: {e}"); }
}
```

Теперь проблемная черта лишит вас только этой черты, а не всего мода, и в логе будет прямо назван сбойный этап:

```text Player.log
[NML]: [HelloBox]: stage 'items' failed: NullReferenceException ...
[NML]: [HelloBox]: HelloBox ready
```

## Не трогайте мир до того, как он появится

`OnModLoad` выполняется **до** генерации игрового мира. Нет карты, нет юнитов, нет ничего. Попытайтесь обратиться к ним там - и игра вылетит еще до главного меню :surprised_pikachu:. Любому коду, работающему каждый кадр, нужна защита:

```csharp Mods/HelloBox/Code/Main.cs
public void Update()
{
    if (!Config.game_loaded) return;                        // всё еще в меню
    if (World.world == null || World.world.units == null) return;  // мира пока нет
    if (MapBox.instance == null) return;

    // отсюда и далее работать с миром безопасно
}
```

## Перезагрузка кода без перезапуска

Перезапуск WorldBox для проверки одной измененной строчки отнимает большую часть времени при создании модов. Спросите любого, кто делал это сорок раз за вечер. NML умеет перекомпилировать мод прямо во время игры и заменять отмеченные методы на лету.

1. Ваш главный класс реализует интерфейс `IReloadable`, содержащий единственный метод `Reload()`. В HelloBox это сделано в **[Готовый мод](#/nml/all-together)**.
2. В меню активных модов NML кнопка перезагрузки появляется автоматически у любого мода, реализующего `IReloadable`. (Старый список модов требовал `Config.isEditor = true`, чтобы показать кнопку, но главное меню не заставляет вас прыгать через этот обруч.)
3. Отметьте нужные методы атрибутом `[Hotfixable]` из пространства имен `NeoModLoader.api.attributes`:

```csharp
using NeoModLoader.api.attributes;

[Hotfixable]
public static WorldTile PickTile(Actor pActor)
{
    // отредактируйте это прямо во время игры, нажмите перезагрузку и смотрите, как следующее существо использует новый код
}
```

Затем измените метод, сохраните файл и нажмите кнопку перезагрузки мода в списке NML. NML перекомпилирует код, пропатчит отмеченные методы и вызовет `Reload()`. Все неотмеченные методы продолжат выполнять старый код.

> [!NOTE] Если вы всё-таки включите `Config.isEditor`
> `Config.isEditor` - это внутренний Unity-флаг игры. Если включить его вручную, WorldBox решит, что работает внутри редактора Unity, и часть интерфейса переключится на мобильную раскладку. С `IReloadable` в современном NML он вам не нужен, так что не трогайте его.

Чего он не умеет: колбэки Unity (`Awake`, `Update` и т.д.), конструкторы и любые объекты, которые игра уже успела создать из вашего старого кода. Ассет, зарегистрированный на старте, сохраняет прежние делегаты — именно в `Reload()` вы можете переназначить их заново вручную.

## Ошибки, которые совершают абсолютно все

| Что происходит | Что это значит |
| --- | --- |
| Мода нет в списке | Нет файла `mod.json` или в нем синтаксическая ошибка (лишняя запятая :pepeclown:) |
| Мод в списке есть, но ничего не происходит | В `OnModLoad` произошел сбой. Ищите в логе имя мода и слово `Exception` |
| `Failed to compile mod ...` | Опечатка в коде C#. Реальная причина указана строкой **выше** |
| `NullReferenceException` на новом ассете | Вы обратились к `base_stats` до вызова `add()` - блок создает библиотека |
| Текст отображается как `trait_whatever` | Забыли перевод, см. **[Локализация](#/nml/localization)** |
| Кнопка выглядит как прозрачная дыра | Неправильно указан путь к спрайту, иконка вернула `null` |
| Работает только у вас, но ни у кого больше | Вы жестко прописали абсолютный путь с именем вашего пользователя Windows :homerhide: |
