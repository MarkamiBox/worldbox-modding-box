# Библиотеки ассетов :wbbrain:

Прежде чем любая из последующих страниц обретет смысл, необходимо усвоить эту. Абсолютно всё в WorldBox (черта, оружие, постройка, плитка, облако, королевство) — это **ассет**, лежащий в **библиотеке**, и каждая библиотека в игре представляет собой один и тот же класс с четырьмя одинаковыми методами.

Освойте их один раз здесь — и остальные тридцать страниц превратятся в простой вопрос: «какая библиотека и какие поля».

## Что представляет собой библиотека

```csharp
public abstract class AssetLibrary<T> : BaseAssetLibrary where T : Asset
{
    public List<T> list;                 // всё содержимое по порядку
    public Dictionary<string, T> dict;   // всё содержимое с доступом по id
}
```

Вот и всё. Список и словарь — оба публичные, оба открыты для чтения и модификации из вашего мода. `AssetManager` содержит 129 таких библиотек. См. **[Все библиотеки ассетов](#/nml/asset-index)** для полного реестра.

## Четыре базовых метода

```csharp
AssetManager.traits.has("hello_swift");            // занят ли этот id?
AssetManager.traits.get("hello_swift");            // получить объект или null
AssetManager.traits.add(myTrait);                  // зарегистрировать новый ассет
AssetManager.traits.clone("hello_new", "brave");   // скопировать существующий и зарегистрировать копию
```

### `has(id)`

Возвращает `true`, если указанный id уже зарегистрирован. **Первая строка каждого создаваемого вами метода `Initialize()` должна выглядеть именно так**:

```csharp
if (AssetManager.traits.has(SWIFT)) return;
```

Без этого повторная перезагрузка мода зарегистрирует всё дважды.

### `get(id)`

Возвращает живой ассет из памяти или `null`, если такого id нет. Метод **не** выбрасывает исключений, поэтому падение из-за отсутствия объекта проявится намного дальше от места ошибки:

```csharp
ActorTrait brave = AssetManager.traits.get("brave");
if (brave == null) return;   // всегда. абсолютно каждый раз.
```

То, что `get` возвращает именно *живой рабочий объект*, — самое ценное знание на этой странице. Это означает, что вы можете модифицировать ванильный контент, не заменяя его:

```csharp
// Делаем ванильных драконов выносливее, не затрагивая ничего остального.
ActorAsset dragon = AssetManager.actor_library.get("dragon");
if (dragon != null) dragon.base_stats["health"] += 500;
```

### `add(asset)`

Регистрирует новый ассет. Внутри происходят три критически важные вещи:

1. **Если id уже занят, старый ассет удаляется, а ваш встает на его место**, оставляя запись в логе:
   ```text
   <e>AssetLibrary<ActorTrait></e>: duplicate asset - overwriting...
   ```
   Именно так один мод тихо ломает другой. Всегда используйте префиксы в id.
2. Для ассета вызывается метод `create()`.
3. **Библиотека выделяет память под `base_stats`** (и под `base_stats_meta`, если оно есть). Вот почему во всем руководстве действует железное правило: «статы настраиваются только после `add()`».

```csharp
ActorTrait swift = new ActorTrait { id = SWIFT, group_id = "physique" };

AssetManager.traits.add(swift);        // <- инициализирует блок статов
swift.base_stats["speed"] = 20f;       // <- безопасно только после этой строки
```

Нарушьте этот порядок — и получите самую популярную ошибку в моддинге WorldBox:

```text
NullReferenceException: Object reference not set to an instance of an object
```

### `clone(newId, sourceId)`

Копирует все сериализуемые поля из `sourceId` в абсолютно новый объект, присваивает ему `newId` **и сам вызывает для него `add()`**. Возвращает полученную копию.

```csharp
BuildingAsset shrine = AssetManager.buildings.clone("hello_shrine", "temple_human");
shrine.max_houses = 0;                     // меняйте только то, что вам нужно
shrine.base_stats["health"] = 200;         // уже доступно, так как add() уже отработал
```

> [!WARNING] Никогда не вызывайте `add()` после `clone()`
> Повторный вызов `add()` удалит только что созданную копию, запишет в лог `duplicate asset overwriting...` и добавит её заново. Код сработает, но лог заполнится мусором, мешающим видеть настоящие ошибки.

Клонирование — правильный выбор по умолчанию для всего, у чего больше десяти полей: построек, существ, предметов, плиток. Вы получаете заведомо рабочую конфигурацию и разбираетесь только с теми полями, которые хотите изменить.

## Шаблоны

В библиотеках хранятся заготовки ассетов, чьи id начинаются со знаков `$` или `_`. Они зарегистрированы в `dict`, но исключены из `list`, поэтому никогда не появляются в игре — они созданы исключительно для клонирования.

```csharp
AssetManager.actor_library.clone("hello_sprite", "$civ_advanced_unit$");
AssetManager.items.clone("hello_sword_ember", "$sword");
AssetManager.buildings.clone("hello_shrine", "$city_building$");
AssetManager.resources.clone("hello_cake", "$TEMPLATE_FOOD$");
AssetManager.kingdoms.clone("hello_sprites", "$TEMPLATE_CIV$");
```

Шаблон практически всегда предпочтительнее готового ассета в качестве основы для клона, поскольку вы не тащите за собой индивидуальность донора. Единственное исключение — графика: клонирование `human` сразу дает спрайты людей, а видимое существо всегда лучше правильного, но невидимого :PES4_AlrightThen:.

## Вывод списка существующих ассетов

Самый быстрый способ узнать доступные для клонирования id — просто распечатать их в консоль:

```csharp
foreach (BuildingAsset asset in AssetManager.buildings.list)
{
    LogInfo(asset.id);
}
```

Две строки — и вам больше никогда не придется угадывать id наугад. Коллекция `list` не содержит шаблоны, а `dict.Keys` включает абсолютно всё.

## Изменение порядка элементов

Коллекция `list` — это обычный `List<T>`, и игра отрисовывает группы и вкладки строго в порядке элементов этого списка. Поэтому вы можете поместить свой ассет в любое нужное место:

```csharp
ItemGroupAsset group = AssetManager.item_groups.get("hello_relics");
int index = AssetManager.item_groups.list.FindIndex(g => g.id == "amulet");

if (group != null && index != -1)
{
    AssetManager.item_groups.list.Remove(group);
    AssetManager.item_groups.list.Insert(index + 1, group);
}
```

## Когда выполняется ваш код

Игра строит все 129 библиотек при запуске, затем вызывает на них `post_init()`, и **только потом** NML загружает ваш мод. Два следствия, на которых люди постоянно спотыкаются, я в том числе:

- **Всё, что библиотека делает автоматически в `post_init`, уже произошло.** Черты акторов, например, получают там `path_icon` по умолчанию. Ваша - нет, потому что её тогда ещё не было. Задайте его сами.
- **Каждый ванильный ассет уже существует, когда выполняется ваш `OnModLoad`.** Поэтому `get("human")` работает, `clone(..., "human")` работает, и правка ванильного контента на месте работает. Вы никогда не опоздаете.

> [!NOTE] Патчи на эти методы не трогают ванильный контент
> `has`, `get`, `add`, `clone` и `post_init` выполняются на всех 129 библиотеках во время запуска игры, ещё до того, как NML загрузит хоть один мод. Патч Harmony на любой из них влияет только на вызовы *после* загрузки вашего мода. Он никогда не затрагивает ванильную регистрацию, которая к тому моменту уже прошла. Хотите другой ванильный контент? Меняйте его после через `get()`, как делает остальная часть этой страницы.

## Универсальный шаблон для всех страниц руководства

```csharp Mods/HelloBox/Code/HelloSomething.cs
namespace HelloBox
{
    public static class HelloSomething
    {
        public const string ID = "hello_something";

        public static void Initialize()
        {
            // 1. защита от повторной регистрации
            if (AssetManager.<library>.has(ID)) return;

            // 2. клонирование аналога или создание с нуля
            SomeAsset asset = AssetManager.<library>.clone(ID, "$template$");

            // 3. изменение нужных полей
            asset.some_field = true;

            // 4. характеристики всегда в самом конце
            asset.base_stats["damage"] = 10;
        }
    }
}
```

Каждая страница руководства по ассетам построена точно по этой схеме, меняются лишь классы и библиотеки. Если вы запутались — возвращайтесь сюда :PESgn_GoOn:.

## Четыре железных правила на стену перед рабочим столом

1. **Сначала `has()`.** Никогда не регистрируйте один и тот же id дважды.
2. **`clone()` уже вызывает `add()`.** Никогда не вызывайте их друг за другом.
3. **`base_stats` появляется только после `add()`.** Статы настраиваются в последнюю очередь.
4. **Ставьте префиксы к id.** `hello_swift`, но ни в коем случае не `swift`. Пространство имен общее для всех существующих модов.
