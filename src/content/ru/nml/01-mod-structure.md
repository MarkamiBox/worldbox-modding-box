# Структура мода :wbsavebuttonbox:

## Где живут моды

Каждый мод - это **отдельная папка** внутри директории `Mods/` в вашей папке WorldBox:

```text
C:\Program Files (x86)\Steam\steamapps\common\worldbox\Mods\
```

Если папки `Mods` там еще нет, создайте её сами: правый клик → Создать → Папку, и назовите её в точности `Mods`. Внутри неё вы создадите папку своего мода с любым придуманным вами именем.

## Как устроен мод

```text
HelloBox/
├── mod.json          <- Паспорт вашего мода (обязательно)
├── icon.png          <- Иконка предпросмотра мода
├── Code/             <- Папка, куда вы складываете свой код
├── Locales/          <- Файлы текстов и переводов (en.json и т.д.)
└── GameResources/    <- Свои текстуры, иконки, пиксель-арт и звуки
```

Каждому моду нужен `mod.json`. HelloBox также нужна своя C#-точка входа. Остальные папки создавайте по мере необходимости. Мод, состоящий только из `mod.json` и `Code/`, уже является полноценным рабочим модом. Пустые папки никого не впечатляют.

#### За что отвечает каждая папка

- **`mod.json`**: Удостоверение личности. Без него NML сделает вид, что вашего мода вовсе не существует.
- **`icon.png`**: Изображение предварительного просмотра, отображаемое во внутриигровом меню модов.
- **`Code/`**: Папка, куда кладутся все ваши файлы исходного кода `.cs` (например, `Main.cs`). На самом деле NML компилирует любой `.cs`-файл, найденный где угодно в вашем моде, включая подпапки (пропуская `bin/`, `obj/`, `Properties/`, `packages/` и любую папку, чьё имя начинается с точки). Поэтому `.cs`-файлы, лежащие прямо рядом с `mod.json`, тоже работают, и некоторые моды так и делают, но `Code/` - это то, что не даёт проекту превратиться в свалку. **NML компилирует исходники, когда это нужно, и может переиспользовать кэш компиляции.** Отдельный шаг сборки для этого руководства не требуется.
- **`Locales/`**: Место хранения файлов локализации (например, `en.json`). Без этого все ваши предметы (item) и черты (trait) будут отображаться в игре как сырые системные ключи.
- **`GameResources/`**: Все ваши текстуры, пиксель-арт, иконки черт, оружия и звуки. Папка должна называться строго так, потому что именно её ищет NML. Подробнее см. **[Спрайты и ресурсы](#/nml/sprites-and-resources)**.

> [!WARNING] Регистр имён папок важен, просто не на вашем ПК
> Windows не важно, написали вы `Locales` или `locales`. Linux - важно. NML ищет `Locales` и `GameResources` с точным написанием, так что мод, который работает у вас, может остаться без текста и без спрайтов у кого-то другого. Совпадите с регистром выше, и проблемы не будет.

#### Папки, которые вы встретите в чужих модах

Ни одна из них не нужна вам для старта. Вы увидите их, когда откроете чужой мод, так что вот что это такое.

| Папка | Назначение |
| --- | --- |
| `Assemblies/` | Сторонние управляемые библиотеки для модов на исходниках. NML собирает `.dll`-файлы прямо внутри этой папки как ссылки для компилятора и пытается их загрузить. Это не место для DLL игры или NML |
| `GameResourcesReplace/` | NML загружает её в точности как `GameResources/`, сразу после неё. NML относит это имя к совместимости с NCMS. В новом моде просто используйте `GameResources/` |
| `EmbededResources/` | Да, с опечаткой, и так и должно быть. Файлы внутри упаковываются в скомпилированный код мода **в стиле NCMS**. Проверенный компилятор исходников читает её только на своей ветке совместимости с NCMS. Это не автоматическое встраивание для кода `BasicMod` в HelloBox. `EmbeddedResources/` - не то имя папки, которое использует эта ветка |

#### Поставка `.dll` вместо исходников

В проверенном загрузчике файл с расширением `.dll` **прямо рядом с `mod.json`** выбирает путь с готовой сборкой. NML пропускает компиляцию исходников и загружает DLL из корня. Положите туда скомпилированную DLL своего HelloBox и не включайте `Code/` в релиз. См. **[Публикация мода](#/nml/publishing)** про проверки сборки и упаковки.

> [!WARNING] Одна случайная .dll отключает весь ваш код
> Именно поэтому библиотека, брошенная рядом с `mod.json`, "ломает" мод на исходниках: NML видит `.dll`, пропускает `Code/`, и ни одно из ваших изменений никогда не загрузится. Библиотекам место в `Assemblies/`, никогда в корне мода.


### Манифест

Файл `mod.json` необходим загрузчику NeoModLoader для идентификации вашего мода :pepeOK:. Он располагается в самом корне папки мода.

```json Mods/HelloBox/mod.json
{
  "name": "HelloBox",
  "author": "yourName",
  "version": "0.1.0",
  "description": "My mod is the best frfr",
  "iconPath": "icon.png",
  "GUID": "com.yourName.hellobox",
  "RepoUrl": "https://github.com/yourName/hellobox",
  "Dependencies": [],
  "OptionalDependencies": [],
  "IncompatibleWith": []
}
```

#### Что означают эти поля?

| Поле | Назначение |
| --- | --- |
| `name` | Отображаемое имя, здесь `HelloBox` |
| `author` | Ваше имя |
| `version` | Версия релиза. Увеличивайте её при публикации |
| `description` | Краткое описание |
| `iconPath` | Путь к иконке относительно папки мода |
| `GUID` | Стабильная идентичность. NML нормализует его в `UID`; для этого примера - `COM_YOURNAME_HELLOBOX`. Не меняйте после релиза |
| `RepoUrl` | Метаданные ссылки на репозиторий или страницу поддержки. Проверьте её отображение в вашей версии NML |
| `Dependencies` | Обязательные id модов. Задокументированный процесс сборки из исходников требует их успешной компиляции |
| `OptionalDependencies` | Опциональные id модов. NML может предоставить их ссылки и символы компилятора во время компиляции исходников |
| `IncompatibleWith` | Объявления конфликтов. Не полагайтесь на одинаковое применение в разных версиях загрузчика |
| `UsePublicizedAssembly` | По умолчанию `true` в проверенном загрузчике. Добавляет ссылку на публицированную сборку игры от NML во время компиляции исходников |

> [!WARNING] Проверьте обработку конфликтов, прежде чем заполнять список
> Встроенная документация описывает `IncompatibleWith` как незавершённую функцию. У установленного загрузчика есть проход удаления, который убирает мод с непустым списком ещё до поиска указанных в нём id. Оставьте пример пустым. Проверьте вашу конкретную версию загрузчика и с конфликтующим модом, и без него, прежде чем публиковать объявление.

#### ModType и targetGameBuild

Проверенное перечисление содержит `NEOMOD`, `COMPILED_NEOMOD`, `BEPINEX` и `RESOURCE_PACK`. По умолчанию - `NEOMOD`; обнаружение DLL в корне выбирает `COMPILED_NEOMOD`.

Имя значения перечисления - не готовый рецепт. Проверенный метод `LoadMod` обрабатывает два типа NeoMod и отклоняет остальные значения на этом пути. Не указывайте `ModType` в манифесте HelloBox. Это руководство не утверждает, что одного `RESOURCE_PACK` достаточно для рабочего пака текстур.

У `targetGameBuild` есть JSON-отображение в сборке, но проверенный конструктор на основе файла не копирует его в активное объявление. Не используйте это поле как проверку совместимости. Укажите версию сборки игры и NML, на которых вы тестировали, в описании релиза.

#### Ключи манифеста не взаимозаменяемы

Проверенное объявление отображает `GUID` в его рабочий `UID`. У него нет отображений для `id`, `mainClass`, `modLoader`, `gameVersion` или `homepage`, и его конструктор на основе файла не читает эти ключи. Они не заменяют поля выше.

NML сам находит подходящий тип точки входа в сборке. Строка `mainClass` его не выбирает. Держите манифест компактным, а не импортируйте схему другого загрузчика.

#### Символы зависимостей

Для **ASCII-идентификаторов, используемых здесь**, NML переводит буквы в верхний регистр и заменяет знаки препинания на подчёркивания: `com.yourname.hellobox-extra` становится `COM_YOURNAME_HELLOBOX_EXTRA`. Не распространяйте это правило на все символы Юникода; проверенный нормализатор часть из них сохраняет как есть.

Во время компиляции исходников NML определяет символ опциональной зависимости, если у этого id есть запись в его карте ссылок компилятора. Одной установки недостаточно для проверки. Он также может повторить неудачную компиляцию без опциональных зависимостей.

> [!WARNING] Опечатка в символе молча убирает код
> Неизвестный символ `#if` равен false. Проверьте id зависимости, список `OptionalDependencies` и нормализованный символ. Успешная компиляция не доказывает, что ваша интеграция была включена.

См. **[Работа рядом с другими модами](#/nml/other-mods)** про полный пример и отдельную проверку во время выполнения.

#### Что ломает папку мода

- **Поставка DLL игры или загрузчика.** Не включайте `Assembly-CSharp.dll`, её публицированную копию, `NeoModLoader.dll`, DLL Unity или другие DLL, скопированные из папки игры `Managed/`. При сборке ссылайтесь на локальные копии; не кладите их в архив. У загрузчика дополнительных библиотек NML есть особые случаи и дедупликация, так что копирование DLL - ненадёжный способ подменить загруженную версию.
- **Вложенные манифесты.** NML сначала проверяет собственный `mod.json` папки мода. Только если его нет, он ищет ниже этой папки. При нескольких вложенных совпадениях проверенный загрузчик выводит предупреждение и использует первый результат. Не полагайтесь на этот порядок. Публикуйте один манифест по пути `HelloBox/mod.json`.
- **Резервные копии исходников внутри мода.** Папка `dist/`, `backup/` или `old/` может дать дублирующиеся C#-классы при компиляции исходников. Держите черновики релиза и резервные копии вне установленного мода.
- **Жёстко прописанные пути.** Внутри своего класса `BasicMod` используйте `GetDeclaration().FolderPath` и `Path.Combine` для упакованных файлов. Директория игры `StreamingAssets/mods` - это место нативного загрузчика, а не папка HelloBox.
- **Пути, выходящие за пределы пакета.** Используйте относительные пути к иконкам и ресурсам с совпадающим регистром. Не поставляйте абсолютные пути или сегменты `..`. `Path.Combine` склеивает пути; он не проверяет, что пользовательский ввод остаётся внутри вашей папки.

> [!NOTE] Что было проверено
> Поведение папок и компилятора здесь прослежено по установленной сборке NML, версия файла `1.2.0.1`, информационный коммит `cd47a1a6c437718d38e8f29240bdb761d543e09a`, вместе со встроенной документацией NML. Это не гарантия для каждого релиза.


## Немного технической теории :elpepehacker:

Каждому моду нужен один C#-файл, говорящий: "Привет, я мод". Вот весь необходимый код:

```csharp Mods/HelloBox/Code/Main.cs
using NeoModLoader.api;

namespace HelloBox
{
    public class Main : BasicMod<Main>
    {
        protected override void OnModLoad()
        {
            LogInfo("Mod loaded successfully!");
        }
    }
}
```

Это не упрощенная демо-версия для руководства: именно с этого скелета начинается подавляющее большинство реальных модов.

#### Разбор кода

- **`using NeoModLoader.api;`**: Это как открыть ящик с инструментами перед началом работы. Вместо того чтобы каждый раз писать `NeoModLoader.api.BasicMod`, директива `using` говорит компьютеру: *"держи инструменты NML готовыми на столе"*.
- **`namespace HelloBox`**: Фамилия для вашего кода. В чужом моде тоже может быть класс `Main`, и пространство имен гарантирует, что они не перепутаются.
- **`public class Main`**: В C# весь код живет внутри "классов". Класс - это просто чертеж или шаблон с собственным именем.
- **`: BasicMod<Main>`**: официальный значок вашего мода. Он говорит NML *«я настоящий мод»*, и взамен NML бесплатно даёт вам логирование, настройки, поэтапную загрузку и переводы. Часть `<Main>` просто повторяет имя вашего класса. Да, выглядит странно, и да, пишется всегда именно так.
- **`protected override void OnModLoad()`**: Кульминационный момент. При загрузке WorldBox загрузчик NML один раз стучится в эту дверь. Всё, что регистрирует ваш мод (черты, предметы, силы), помещается внутрь этих фигурных скобок `{ }`.
- **`LogInfo(...)`**: Выводит строчку в лог с уже подставленным именем вашего мода. Так вы убедитесь, что код вообще выполнился. См. **[Логи и отладка](#/nml/logs-and-debugging)**.

> [!TIP] Длинный путь
> В старых модах вы можете увидеть такую запись. Да, я достаточно стар, чтобы помнить времена, когда это было нормой:
> ```csharp
> public class MyMod : MonoBehaviour, IMod
> {
>     private ModDeclare _declare;
>
>     public void OnLoad(ModDeclare pModDecl, GameObject pGameObject)
>     {
>         _declare = pModDecl;
>     }
>
>     public ModDeclare GetDeclaration() => _declare;
>     public GameObject GetGameObject() => gameObject;
>     public string GetUrl() => _declare.RepoUrl;
> }
> ```
> `IMod` - это чистый интерфейс, а `BasicMod<T>` - готовый класс, который реализует его и добавляет массу удобств. Работают оба варианта. Используйте `BasicMod`, если у вас нет особых причин делать иначе, и теперь вы знаете, что такое второй вариант, когда встретите его в чужих исходниках :PES5_Noted:.
