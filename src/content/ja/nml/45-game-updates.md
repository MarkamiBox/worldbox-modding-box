# ゲームのアップデート後にmodを更新する :wbsettingsgear:

WorldBoxがアップデートされて、あなたのmodがリストで赤くなっている。modding へようこそ。誰にでも起きることだし、これからも起きます :PES2_Shrug:。

modはゲーム自身のコードを呼び出しています。開発者がメソッドの名前を変えたり、フィールドを移動したり、メソッドが受け取るものを変えたりすると、あなたのコードはもう存在しないものを指すことになります。直せないほど壊れたわけではなく、古くなっただけです。このページは、私が毎回確認している順番です。

## 1. まずNMLを更新する

自分のコードに触る前に、**[NMLのインストール](#/install-nml)** ページから最新の **`NeoModLoader.dll`** を入手してください。ゲームの大型アップデートには、たいてい新しいNMLもついてきます。古いローダーを新しいゲームで動かすと、まるで自分のミスのように見える形で失敗します。

NML自体が読み込まれないなら、まだあなたのmodの段階ではありません。トラブルシューティングの **[ゲームが古いバージョンのまま](#/troubleshooting)** を確認してから戻ってきてください。

## 2. 最初のエラーを読む

ゲームを起動してから `Player.log` を開きます（場所は **[ログとデバッグ](#/nml/logs-and-debugging)**）。あなたのmodの最初のエラーを見つけ、その下はひとまず全部無視してください。エラーは連鎖するので、最初のひとつを直すと他の5つが消えることもよくあります。

アップデート後によく見るのはこれらです：

| エラー | ゲームで何が変わったか |
| --- | --- |
| `CS0117: 'X' does not contain a definition for 'Y'` | フィールドか静的メソッドの名前が変わったか、削除された |
| `CS1061: 'X' does not contain a definition for 'Y'` | 同じだが、オブジェクト側：`actor.someMethod()` がもうない |
| `CS0246: The type or namespace name 'X' could not be found` | クラスごと名前が変わったか、移動した |
| `CS7036` / `CS1501` | メソッドはまだあるが、受け取る引数が変わった |
| `CS0122: 'X' is inaccessible due to its protection level` | 使っていたものが `internal` になった。**[その項目](#/troubleshooting)** を参照 |
| `CS0029` / `CS0266` | フィールドの型が変わった。たとえば `int` から `float` へ、または文字列からアセットへ |
| 起動時の `HarmonyException` / `MissingMethodException` | あなたが**パッチしている**メソッドの名前が変わった。コードはコンパイルできるが、パッチの取り付け先がない |

最後のものがいちばん厄介です。`"updateStats"` のように、メソッド名をただの文字列で書いたパッチは、ゲームの起動時にしかチェックされません。つまり名前が変わってもmodのコンパイルは止まらず、動作だけが止まります。`nameof` で書いたパッチなら普通のコンパイルエラーになるので、使える場所では使う理由がもうひとつ増えます（**[メソッド名の2つの書き方](#/nml/harmony-patches)**）。

## 3. 新しい名前を見つける

古い名前は消えたので、代わりを探します：

- このサイトの **[メソッド検索](#/tools/methods)**。メソッドの名前ではなく、*何をしていたか*を入力してください。"add trait to unit" なら、名前が変わっていても見つかります。
- アセットのフィールドは **[アセットのフィールド](#/tools/fields)** で。覚えている部分の名前で検索します。
- **dnSpy**。あなたが実際に持っているゲームを読むので、常に正しいです。このサイトの検索ツールはアップデート後に作り直されますが、出たばかりのアップデートには数日遅れることがあります。使い方は **[ゲームのコードを読む](#/toolbox/reading-the-game-code)**。

私がいちばん使うコツ：あなたのものと同じ役割のバニラのアセットやメソッドを開いて、**ゲーム自身**が今どう書いているかを見ることです。ゲームが特性（trait）の作り方を変えたなら、ゲーム自身の特性はすでに新しい書き方を使っています :PESgn_Noice:。

### もう存在しない名前

古いmod、古いチュートリアル、古いフォーラムの投稿にはこういうものがたくさん出てきます。今のゲームにはどれ一つ存在しないので、それぞれコンパイルエラーになるか、テンプレートidの場合は起動時に `clone()` が `KeyNotFoundException` を投げます：

| 古い名前 | 今使うもの |
| --- | --- |
| `AssetManager.unitStats` | `AssetManager.actor_library`。生物は `ActorAsset` です。**[カスタムアクター](#/nml/custom-actors)** を参照 |
| `AssetManager.raceLibrary` | 直接の代わりはありません。かつて race が持っていたものは今 `ActorAsset` 自体にあります |
| `AssetManager.nameGenerator` | `AssetManager.name_generator`。**[名前生成器](#/nml/name-generators)** を参照 |
| `AssetManager.items_material_weapon`, `items_material_accessory` | 代わりのライブラリはありません。各素材は `AssetManager.items` の中の独立したアイテムです（`sword_iron`、`sword_steel`）。**[カスタムアイテム](#/nml/custom-items)** を参照 |
| `"!building"`（建物テンプレート） | `AssetManager.buildings` の `"$building$"` |
| `"_spawn_building"`（ドロップテンプレート） | `AssetManager.drops` の `"$spawn_building$"` |
| `"_dropBuilding"`（神の力テンプレート） | `AssetManager.powers` の `"$template_drop_building$"` |

最後の3つに共通するパターンが覚えておくべきポイントです。テンプレートは今 `$` で囲まれるようになりました。古い `clone()` が `_` や `!` で始まるidを使っているなら、同じライブラリの `init()` の中で `$...$` 版を探してください。

## 4. Harmonyパッチを手で確認する

パッチは、エラーがひとつも出ないまま壊れることもあります。ひとつずつ見て、dnSpyでメソッドを確認してください：

- **パラメータ名。** Harmonyはパラメータを**名前で**埋めます。ゲームが `pDamage` を `pAmount` に変えたら、あなたの `float pDamage` はもう結び付かず、Harmonyはパッチの適用時に失敗します。**[魔法のパラメータ名](#/nml/harmony-patches)** を参照。
- **オーバーロード。** 以前はひとつだけだったメソッドに双子ができて、パッチが `Ambiguous match found` で失敗することがあります。
- **メソッドがやっていること。** 名前はそのままで、処理だけが別の場所に移ることもあります。パッチは動くのに何も変わりません。パッチに `LogInfo` を1行入れてください。一度も表示されないなら、ゲームはもうそのメソッドを呼んでいません。

## 5. 何もしなくなったものを探す

もう一度コンパイルできたらゴール、ではありません。ワールドを読み込んで、すべての部品がまだ動くか確認してください：特性にアイコンが出る、アイテムが落ちる、パワー（GodPower）が出すべきものを出す。

新しいアップデートで、バニラのアセットは埋めているのにあなたのものは埋めていないフィールドが増えることがあります。アセットは読み込まれ、エラーもなく、ただ何もしません。あなたのアセットを、そのライブラリの `init()` にあるいちばん近いバニラのものとフィールドごとに比べてください。ゲームが今は設定していて、あなたが設定していないものが容疑者です。

## 6. 古いセーブもテストする

アップデート**前**に保存したワールドを、modを有効にして読み込みます。ユニットに保存した独自データ（**[データの保存](#/nml/saving-data)**）は、そのまま戻ってくるはずです。修正中にIDの名前を変えた場合、古いセーブはまだ古いIDを使っているので、本当に必要なときだけ変えてください。

## 7. リリースする

- `mod.json` の `version` を上げる。
- 説明と変更履歴に、どのゲームバージョンで動くかを書いて、プレイヤーがどれを選べばいいか分かるようにする。
- 新しいzipを前と同じ方法でアップロードする：**[公開](#/nml/publishing)**。

それから「アプデ対応した？？」のコメントに返事をしましょう。あなたにはその資格があります :wbsalut:。

## 次のアップデートを少しでも楽にするために

- **パッチを減らす。** Harmonyのパッチはひとつひとつが壊れうる場所です。アセットのフィールドやNMLの機能で済むなら、そちらを使いましょう。
- **コードを try/catch で包む。** 壊れた機能はログにエラーをひとつ書くだけで、modの残りは動き続けます。**[ログとデバッグ](#/nml/logs-and-debugging)** を参照。
- **ひとつの仕事にひとつのパッチクラス。** 失敗の切り分けがしやすくなります。ただし `PatchAll` の失敗そのものは切り分けられません。対象がひとつ見つからないだけで、それより後のパッチが適用される前にスキャンが止まることがあります。任意対象には手動でガード付きパッチを使ってください。
- **IDは一か所にまとめる。** `HelloTraits.SWIFT` のような定数があれば、名前の変更は20か所ではなく1か所の修正で済みます。
