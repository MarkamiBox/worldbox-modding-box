# Modの公開 :wbfireworks:

Modが動きました。今度は他のプレイヤーに壊してもらいましょう。

WorldBoxのModを公開できる場所は主に2つありますが、利用実態は大きく異なります：

| | |
| --- | --- |
| **[GameBanana](https://gamebanana.com/games/11196)** | WorldBoxのModコミュニティが実際に集まる中心地。Steam以外でゲームを購入したプレイヤーも含め、誰でもダウンロードできます |
| **Steam Workshop** | NMLに統合されていますが、Modの登録数は大幅に少なめです |

まずはGameBananaで公開しましょう。気が向いたら後からWorkshopにも登録する、という流れがおすすめです。

## Mod のパッケージング

GameBananaにアップロードするファイルは、単なる**Modフォルダのzip圧縮**です。それ以上でもそれ以下でもありません。zipの中身は、直下に `mod.json` があるフォルダ構成にしてください：

```text HelloBox.zip
HelloBox/
├── mod.json
├── icon.png
├── default_config.json
├── Locales/
├── GameResources/
└── Code/
```

中身だけをzipにするのではなく、**親フォルダごとzip**にしてください。誰かが `Mods/` フォルダに解凍したとき、`Mods/HelloBox/mod.json` になる必要があります。もし `Mods/mod.json` になってしまうと、「Modが読み込まれません」と報告が届くことになります :PES_Facepalm:。

動作に不要なものは**すべて除外**してください：`.git/`、`bin/`、`obj/`、`.vs/`、`.sln`、メモ帳など。ビルド済みの `.dll` を同梱する場合は、古いソースコードと一緒に置くのではなく、`Code/` の*代わりに* `.dll` を配置してください。

## GameBanana へのアップロード

1. アカウントを作成し、**[WorldBoxのゲームページ](https://gamebanana.com/games/11196)** へ行きます。
2. **Add → Mod** をクリックします。
3. 名前、説明文、カテゴリを入力します。カテゴリは想像以上に重要で、プレイヤーがあなたのModを見つける唯一の手段です。
4. zipをアップロードし、少なくとも1枚は**ゲーム内でModが実際に何かをしているスクリーンショット**を投稿してください。アイコン画像やMod一覧のスクショではありません。
5. 説明欄には「何を追加するのか」「**NeoModLoader** が必須であること」「競合するMod」を明確に記載してください。

後からの更新も同じページの **Edit → Files** から行えます。新しいzipを追加し、更新履歴を1行書き、`mod.json` の `version` をそれに合わせて更新します。GameBananaのバージョンと `mod.json` のバージョンを常に一致させておけば、「どのバージョンが入っているか」という質問をゼロにできます。

> [!TIP] 1枚のスクショは長文に勝る
> プレイヤーはサムネイルで導入を決めます。Modが何を追加するのかを示す明確なインゲームの画像1枚は、どれほど美しく書かれた説明文よりも効果的です :PES_Camera:。

## Steam Workshop での公開

Workshopへのアップロードは**ゲーム内**から行いますが、そのアップロード画面の開き方はこの界隈で最も呪われたUI仕様となっています :kekw:。

1. ゲーム内で **Mods** ウィンドウを開きます。
2. 自分のModの**アイコン**を、1秒未満の間隔で正確に**8回連続クリック**します。
3. 約3秒待ちます。
4. アップロード画面が表示されます。

何も起きない場合はクリックが遅すぎたか、アイコンではなく行の部分をクリックしてしまっています。

新しくなったNMLのMod一覧画面では、選択したModのフォルダを開いたり有効化の切替やコードの再読込を行うボタンも用意されていますが、アイコンを8回クリックする秘密の儀式はSteamアップローダーを呼ぶ方法として健在です :PES2_Shrug:。

| 項目 | 入力内容 |
| --- | --- |
| 上の欄 (`fileID`) | **初回は空欄のまま**にします。更新時はWorkshopアイテムのURLに含まれるIDを貼り付けます |
| 下の欄 | 変更履歴。空欄でも構いません（後からWorkshopページで編集可能） |

新規公開とアップデートの違いはこれだけです。`fileID` が空なら新規作成、入力されていれば既存アイテムの上書き更新になります。

### 初回の認証手続き

Workshopに新しいModをアップロードする際、認証を求められます。方法は3つあります：

- **Discord**: 公式WorldBox Discordの管理者に問い合わせて `Modder` ロールを付与してもらう。
- **GitHub**: `WorldBoxOpenMods` オーガニゼーションに参加する。件名を「WorldBoxOpenMods」とし、GitHubユーザー名とModを記載したメールを送り、最大1週間待つ。
- **スキップ**: `Unverified Mods`（未検証Mod）タグ付きでそのままアップロードする。これでも普通に機能しますが、一覧での露出度が下がります。

## アップロードボタンを押す前の最終確認

- **`mod.json` はあなたの店のショーウィンドウです。** `name`、`author`、`version`、`description` をプレイヤーは見ています。リリースごとに `version` を更新し、初回アップロード後は**絶対に `GUID` を変更しないでください**。GUIDはModの固有IDであり、プレイヤーの設定ファイル名や他Modの依存関係の基準になっています。
- **`icon.png` を用意し、見栄えを整える。** Workshopでは8回連打される対象でもあるため、見ていて心地よい画像にしましょう。
- **Modが任意のフォルダ名で動くことを確認する。** `C:\Users\YourName\...` のような絶対パスをハードコードしてはいけません。`GetDeclaration().FolderPath` を使ってください。「作者の環境でしか動かない」最大の原因がこれです :PES2_Bruh:。
- **自分のログを一度きれいな状態で通して読む。** ゲームを起動し、ワールドを読み込み、2分間プレイしてから、`Player.log` で自分のプレフィックスと `Exception` を検索してください。例外は1つも残さないでください。
- **設定ファイルを削除した状態でテストする。** `mods_config/<GUID>.config` を削除し、新規プレイヤーが受け取るデフォルト設定で動作するかテストしてください。
- **他のModを有効にした状態でテストする。** あなたがパッチした箇所は、他の誰かもパッチしています。
- **新規セーブデータでテストする。** 登録したアセットは、それを参照するセーブデータが読み込まれる前に存在していなければなりません。

## Dependencies

他のModが必要な場合は、型の欠落でクラッシュさせるのではなく依存関係を明記してください：

```json mod.json
{
  "Dependencies": ["com.otherperson.coolmod"],
  "OptionalDependencies": ["com.someone.niceextra"],
  "IncompatibleWith": ["com.someone.rivalmod"]
}
```

NMLがロード順序を適切に制御し、不足していればプレイヤーに警告を出してくれます。1行目でNullReferenceExceptionを起こすよりずっと親切です。

## リリース後のメンテナンス

コメント欄に届くメッセージは、正確に3種類しかありません。「動きません（ログなし）」、自分では思いつかなかった本当に素晴らしいアイデア、そしてマルチプレイを要求する声です :PESgn_DidIAsk:。

2つ目には返信しましょう。1つ目に対しては、`Player.log` の場所を記載したコメントをピン留めしておいてください（**[ログとデバッグ](#/nml/logs-and-debugging)** 参照）。ログのないバグ報告には、開発者としても手の打ちようがないからです。

そして、ようこそ。新しいModが1つ出るたびに、この小さなコミュニティは少しだけ墓場ではなくなります。1週間に5つも出たら、それはもうModdingの黄金時代（world age）です :PES5_CrazyPog:。
