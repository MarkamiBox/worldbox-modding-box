## modを使う

これはmodを作る人ではなく、遊ぶ人のためのグループです。これより下はコードを書く人向けです。

### 画面が赤文字で埋め尽くされる

- **症状**：ゲーム画面に赤い文字が流れ続け、`previous errors repeated`、`YOU SHOULD RESTART THE GAME` と表示され、ログには `Missing className: NeoModLoader (1).WorldBoxMod` とあります。
- **原因**：ファイル名が `NeoModLoader.dll` になっていません。ブラウザが2回目のダウンロードで名前に ` (1)` を付け、NMLは自分のファイル名を読み取っています。
- **対処**：ゲームを閉じ、古いコピーを削除し、ファイル名を正確に `NeoModLoader.dll` に変更して再起動します。詳しい手順は **[NMLのインストール](#/install-nml)** を参照。

### アップデート後にmodが赤や失敗になる

- **症状**：mod一覧でmodが赤や「failed」、`current failed, will load`、`<Mod> has been disabled due to an error` と表示されます。アップデート前は動いていました。
- **原因**：modはゲーム自身のコードを呼び出しています。WorldBoxがそのコードを変えると、古いバージョン向けのmodはコンパイルできなくなります。NMLは悪くなく、ただの伝達役です。
- **対処**：そのmodの新しいバージョンを探します（GameBananaで **Updated** 順に並べ替え）。新しいバージョンがなければ、作者を待つか、古いバージョンのゲームで遊びます。**[FAQ](#/install-nml)** を参照。同じmodを念のため2つ `Mods` に置かないこと：喧嘩します。

### ゲームが古いバージョンのまま動かない

- **症状**：NMLがまったく読み込まれない、またはログに `MissingFieldException: Field not found: bool .Config.gameLoaded` と出ます。メインメニューのバージョン番号が、みんなが話しているものより古いです。
- **原因**：ゲームがSteamの**ベータブランチ**になっています。たいていは以前アップデートを早く試すために選んだままで、ダウンロードしたNMLは現在のバージョン向けです。
- **対処**：Steam → WorldBoxを右クリック → **プロパティ → ベータ** → **なし**。Steamに更新させ、Experimental Modeを再度オンにします :PES2_Shrug:。

### modを入れると重くなるか固まる

- **症状**：FPSが低い、カクつく、またはボタンは反応するのにワールドだけ固まります。modなしでは問題ありません。
- **原因**：ほぼ必ず、毎tick重い処理をしているmodが1つあります。大きなコンテンツmodによく見られます。同じものを変更する2つのmodが互いをロックすることもあります。
- **対処**：modを半分オフにして再起動、確認。まだ壊れていれば、オンにしている半分の中に犯人がいます。1つになるまで半分ずつ絞り込みます。オフにするだけで十分で、削除の必要はありません。そのmodの説明で既知の非互換情報を確認し、同じmodのフルバージョンとliteバージョンを同時に動かさないこと。

### ワールドが読み込めなくなった

- **症状**：セーブを開くと別のワールドになる、読み込み中に止まる、またはセーブ・ロード中に `NullReferenceException` が出ます。
- **原因**：ワールドの中に、今はオフ・削除・古くなったmodの生物・建物・特性が含まれています。ゲームが知らないidを見つけています。
- **対処**：そのmodを再びオンにする（またはセーブが作られたバージョンに戻す）、ワールドを読み込み、mod関連のコンテンツをゲーム内で取り除いてからmodを外します。新しいコンテンツmodを試す前に、大事なワールドはコピーしておきましょう :PES_MonkaSweat:。

### BepInExのmodを入れても何も出ない

- **症状**：modが `BepInEx/plugins` に入っているのに、ゲーム内に何も表示されず、`BepInEx/config` に専用の設定ファイルもできません。
- **原因**：zipファイルのままを `plugins` に入れてしまっているか、BepInExのマネージャーオブジェクトがゲームに破棄されています（一部の環境では設定が必要です）。
- **対処**：zipの**中にあるフォルダ**を `BepInEx/plugins` に入れます。zipそのものではありません。次に `BepInEx/config/BepInEx.cfg` を開き、`HideManagerGameObject = false` を見つけて `true` に変更、保存して再起動します。BepInEx自体の導入は **[ライブコンソール](#/toolbox/bepinex-console)** を参照。

### modを消したのにまだ残っている

- **症状**：`Mods` からフォルダを消したのに、そのmodは読み込まれ続けます。
- **原因**：Steam Workshopで購読していたmodです。Workshopのmodはあなたのフォルダではなく、Steam自身のフォルダに入っています。
- **対処**：Workshopのページで購読解除します。一覧のチェックを外すだけでは同じではありません。

### ゲームがまったく起動しない

- **症状**：modを外した後でも、WorldBoxがメインメニューの前に閉じる、またはフリーズします。
- **原因**：ゲーム本体のファイルが壊れています。多くの場合、何かを間違ったフォルダにコピーしたのが原因です。
- **対処**：Steam → WorldBoxを右クリック → **プロパティ → インストール済みファイル → ゲームファイルの整合性を確認**。それからNMLとmodを1つずつ戻します。

## 何も読み込まれない

ゲームがまるであなたのModが存在しないかのように振る舞います。個人的な恨みではありません、たいていはスイッチ1つかファイル名1つです。

### メニューに Mods ボタンが表示されない

- **症状**：ゲームは普通に起動し、エラーもなく、Modsボタンもなく、ログのどこにも `[NML]` の行がない。
- **原因**：「Mods」という名前のフォルダーが2つあります。ローダーのDLLはゲームのデータフォルダーに入れ、`worldbox\Mods/` は*あなたの*Mod用です。
- **解決策**：`NeoModLoader.dll` を `worldbox\worldbox_Data\StreamingAssets\mods/` に置いて再起動し、ログで `[NML]: NeoModLoader Version:` を探してください。Macも含めたすべての手順：**[NMLのインストール](#/install-nml)**。

### Mods ウィンドウが空（以前は動いていた）

- **症状**: ウィンドウは開くが一覧に何も表示されない。エラーなし。
- **原因**: **実験モード（Experimental Mode）がオフ** になっています。WorldBoxのアップデートごとに自動でオフに戻ります。
- **解決策**: 設定 → 実験モード → オン → 再起動。

### Mod フォルダはあるのに一覧に表示されない

- **症状**：リストに何もなく、`Compile Mod <yours>` の行もない。
- **原因**：よくある順に：ファイルが実は `mod.json.txt`；JSONが不正（最後の項目の後のカンマ、またはチャットアプリから貼り付けた曲がった `"` 引用符）；フォルダーが `worldbox\Mods/` の中にない。
- **解決策**：エクスプローラー → **表示 → 表示 → ファイル名拡張子** をオンにして、本当の名前を確認します。`mod.json` はJSONのエラーに下線を引いてくれるVS Codeで開きましょう。

### Mod がグレーアウトしている

- **症状**：灰色で表示され、コードが一切動かない。
- **原因**：無効化されていて、その状態が `StreamingAssets\mods\NML\mod_compile_records.json` にディスク上で記憶されています。
- **解決策**：Modsウィンドウでそのmodのアイコンをクリックし、再起動してください。

### "Compile failed" のエラー意味がわからない

- **症状**: `Code\Main.cs(9,42): error CS1002: ; expected` 等が出る。
- **原因**: 最後のまとめ行ではなく、その上の行に正確なファイル名・行番号・エラー原因が書かれています。
- **解決策**: **最初の1つのエラーだけ** を修正して再起動してください。

| コード | 意味 |
| --- | --- |
| `CS1002` | セミコロン `;` の不足 |
| `CS0246` | 不明な型名（`using` の書き忘れなど） |
| `CS0266` | `int` 型に `float`（`0.5f`）を代入している等の型不一致 |
| `CS0122` | メンバーが `internal` です。[該当項目](#cs0122-inaccessible-due-to-its-protection-level) を参照 |

### 貼り付けたコードの1行目でエラーが出る

- **症状**：意味不明に見えるコンパイルエラーが1行目で出る。
- **原因**：このサイトのコードブロックにはファイルパスのラベルが付いています。少しだけ上まで選択しすぎると、そのラベルが `.cs` の中に入ってしまいます。
- **解決策**：1行目を消してください。`.cs` は `using`、`namespace`、またはクラスで始まり、`mod.json` は `{` で始まります。

### コードを編集したのに反映されない

- **症状**：前の動作のまま、エラーもない。
- **原因**：NMLは `Code\*.cs` を**起動時に一度だけ**コンパイルします。起動中のゲームがファイルを読み直すことはありません。
- **解決策**：保存して、完全に終了し、もう一度起動してください。再起動1回につき変更は1つ。そうすれば壊れたときの容疑者は1つです。

### メモ帳でゲームフォルダ内に保存できない

- **症状**：再起動して、ログには `Compile Mod` と出るのに、ゲームは古いコードのまま動く。コンパイルは一瞬で終わる。
- **原因**：`Mods/` 内の2つのフォルダーが、`mod.json` の中で同じ `GUID` を持っています。よくあるのは、NMLのインストーラーが `COM_YOURNAME_HELLOBOX/` として展開した古いコピーです。NMLは**GUIDごとに1つのModだけ**を読み込み、もう片方のフォルダーは黙って無視します。そしてそれが、まさにあなたが編集しているフォルダーかもしれません。
- **解決策**：`Mods/` で自分のGUIDを検索し、フォルダーを1つだけ残してください。数字が合わないときに真っ先に確認すべき点です。

### 変更が再起動しても反映されない

- **症状**：「この場所に保存する権限がありません」と出て、代わりにドキュメントを勧められる。
- **原因**：ゲームはWindowsが保護している `C:\Program Files (x86)/` の下にあります。
- **解決策**：先にエクスプローラーでファイルを作り（右クリック → 新規作成 → テキスト ドキュメント、名前を変更）、その既存のファイルを編集してください。

## 読み込まれるが、画面に何も出ない

NMLはあなたのModを見つけて実行しました。その中の何かが、画面まで届かなかったのです。

### ステータスを設定した行でクラッシュする

- **症状**：`Initialize()` の中で `NullReferenceException` が出て、それ以降が一切実行されない。
- **原因**：作ったばかりのアセットには**ステータスブロックがありません**。ライブラリが `add()` の中で作ります。
- **解決策**：先に `add()`、ステータスはその後。特性、ステータス効果、アイテム、建物、アクター、すべて同じルールです。

```csharp
ActorTrait swift = new ActorTrait { id = SWIFT, group_id = "physique" };
AssetManager.traits.add(swift);      // ここで base_stats が生成される
swift.base_stats["speed"] = 20f;     // ここから安全にアクセス可能
```

`clone()` は `add()` を呼んでくれるので、クローンの後ではブロックはすでに存在します。

### 記述順は正しいのに同じクラッシュが起きる

- **症状**：同じ `NullReferenceException` が、`add()` の後で実行されるステータスの行で出る。
- **原因**：ステータス名をでっち上げています。未知のステータスIDは何もしないのではなく、クラッシュします。
- **解決策**：本物のIDを使ってください：`damage`、`health`、`speed`、`armor`、`attack_speed`、`stamina`、`mana`、`range`、`critical_chance`、`lifespan`、`warfare`。倍率は別物です：`multiplier_damage`、`multiplier_health`、`multiplier_speed`。完全なリストは **[ステータス一覧](#/nml/stats)** にあります。

### 設置した建物が即座に消える、またはサイズがない

- **症状**：建物が現れてすぐ消える、または対象にできない。エラーはない。
- **原因**：建物のデフォルトの `health` と `size` は `add()` の中でしか設定されず、しかもそれは `base_stats` がまだnullのときだけです。先に自分でブロックを作ると `health = 0` になります。
- **解決策**：`base_stats` を事前に作らないでください。先にクローンか `add()` をして、違うべきところだけを変えます。

### 登録したのにどのタブにも表示されない

- **症状**：ログの行は出て、例外もないのに、どのカテゴリーにも表示されない。
- **原因**：`group_id` が存在しないグループを指しているので、描画するタブがありません。
- **解決策**：本物のグループIDを使ってください。アクターの特性なら：`cognitive`、`mind`、`spirit`、`physique`、`health`、`body`、`appearance`、`protection`、`skills`、`merits`、`acquired`、`fun`、`fate`、`miscellaneous`、`special`。独自のタブは：**[特性グループとタブ](#/nml/trait-groups)**。

### 名前の代わりに `trait_hello_swift` と表示される

- **症状**：画面に生のキーが出て、ツールチップは空で、ログに `missing text:` と出る。
- **原因**：翻訳が登録されていません。ゲームはキーを自分で組み立てます：`trait_<id>` と `trait_<id>_info`。
- **解決策**：その2つのキーを `Locales/en.json` に追加してください。`en.json.txt` に注意。

### 特性の名前は出るが、アイテムやステータス、パワーが出ない

- **症状**：特性のやり方を真似したのに、これだけは生のキーのまま。
- **原因**：4つのアセットはIDからキーを組み立て**ません**：

| アセット | 名前のキー | 説明のキー |
| --- | --- | --- |
| `GodPower` | `name` **フィールド**（snake_case） | `<name>_description` |
| `ItemAsset` | `translation_key`、なければ `item_<subtype or id>` | `<id>_description`、`item_` なし |
| `StatusAsset` | `locale_id` **フィールド** | `locale_description` **フィールド** |
| `WorldLawAsset` | `<id>_title` | `<id>_description` |

- **解決策**：パワーには `name` = ID、アイテムには `translation_key`、ステータスには `locale_id` を設定してください。キーは小文字のsnake_caseにしましょう：保存時には正規化されますが、検索時には**されない**ので、`MyKey` は `my_key` として保存され、二度と見つかりません :PESgn_SMH:。

### アイコンが透明な空白になる

- **症状**: アイコンの位置が空白になる。
- **原因**: 間違ったパスを指定すると `null` がセッション中キャッシュされます。
- **解決策**: 拡張子なし・スラッシュ区切り（`/`）で `path_icon` を指定し、ゲームを再起動してください。

### ボタンの枠はあるのに何も描画されない

- **症状**：タブに、誰もクリックしない隙間ができる。
- **原因**：`null` のスプライトはプレースホルダーではなく、まったくの無です :PES4_Invisible:。
- **解決策**：スプライトを確認せずに渡さないでください。`ui/Icons/iconQuestionMark` にフォールバックすれば、ひと目で「パスが違う」と分かります。ヘルパーは **[パワータブとボタン](#/nml/power-buttons)** にあります。

### ステータス効果のスプライトがユニット上に描画されない

- **症状**: 生物の上に何も描かれないか、ステータスが続く間 **毎フレーム** `Status.updateAnimationFrame()` で `NullReferenceException` が出る。
- **原因**: `StatusLibrary` はゲームのロード中に一度だけ、`"effects/" + texture` から `sprite_list` を埋めて `need_visual_render` を立てます。modより前です。しかも `texture` はPNG1枚ではなく、フレームの **フォルダ** の名前です。
- **解決策**: フレームを `GameResources/effects/fx_hello_status/` に置き、`add()` の後で：

```csharp
cursed.sprite_list = SpriteTextureLoader.getSpriteList("effects/" + cursed.texture);
cursed.need_visual_render = true;
```

### ボタンが重なって表示される

- **原因**: `recalc()` だけでは整列されません。
- **解決策**: `tab.recalc();` と `tab.sortButtons();` の両方を順に呼び出してください。 ただし `OnModLoad` の中ではだめ。そこで `recalc()` を呼ぶと落ちます。**[パワータブが出てこない](#パワータブが出てこない)** を参照。

### ボタンはあるが、クリックしてもパワーが発動しない

- **症状**：カーソルが変わらず、マップをクリックしても何も起きない。
- **原因**：ボタンは**作成時に、IDで**パワーに結び付けられます。
- **解決策**：先にパワーを登録し、その後でボタンを作ってください。順番がずれないよう、同じヘルパーの中で。そして `click_action` は `(WorldTile, string)` です。`(WorldTile, GodPower)` の形は `click_power_action` のものです。

### `addOpposite` / `addDecision` / `addSpell` が効かない

- **症状**：対立する特性が外されない、意思決定が発動しない。何のメッセージもない。
- **原因**：これらの呼び出しは**ID**を追加するだけです。IDを実際のオブジェクトに変えるのは、あなたのModが読み込まれる前、起動時に一度だけです。
- **解決策**：`add()` の後で、解決済みのフィールドを自分で埋めてください：`linkCombatActions()`、`linkSpells()`、`decisions_assets`（`AssetManager.decisions_library.get()` から自分で作る配列で、リンク用メソッドはありません）、そして `opposite_traits` は直接代入します。`opposite_trait_mod` を設定して `opposite_traits` をnullのままにすると、後でゲームの社会系コードの中でクラッシュします。空の `HashSet` で防げます。

## 登録できたのに、ワールドで壊れる

このセクションの項目はすべて同じ原因です。ゲームは各アセットの一部を **ロード中に一度だけ** 準備し、modはそのあとでアセットを登録します。何の知らせもありません。アセットは存在し、名前もあり、ゲームが初めて本当に使った瞬間に例外が出ます。対処もいつも同じ形です。アセットを登録した直後に、その一手を自分でやる :wbfacepalm:。今日の言葉：回避策。

### 生物が影のエラーを出す

- **症状**: `ActorAssetLibrary: Shadow size is too small : (0.00, 0.00)` が生物ごとに3回、ゲーム内にエラーのポップアップ。
- **原因**: ライブラリは起動時に各アクターの影スプライトを測ります。後から足した生物は一度も測られません。
- **解決策**: 複製の後で `asset.texture_asset.loadShadow();`。**[カスタムアクター](#/nml/custom-actors)** を参照。

### trait、アイテム、生物がロックされたまま

- **症状**: 存在はするが、知識の書では灰色で、ワールドで出会うまでプレイヤーは使えない。
- **原因**: アンロックできるものはすべて `needs_to_be_explored` が既定で `true` です。アクター、7種類のtrait、アイテム、アイテム修飾、ワールドロー。
- **解決策**: 作るときに `needs_to_be_explored = false`。**[カスタムtrait](#/nml/custom-traits)** を参照。

### 武器や食べ物の読み込みでゲームが落ちる

- **症状**: `ItemLibrary.loadSprites()` か `ResourceLibrary.loadSprites()` で `ArgumentNullException: Value cannot be null. Parameter name: key`。
- **原因**: 武器の `path_gameplay_sprite` とリソースの `full_sprite_path` は、ゲーム自身のロード中に `post_init()` で導かれます。あなたのものは `null` のまま。
- **解決策**: 自分で設定する。**[カスタムアイテム](#/nml/custom-items)** と **[リソースと食べ物](#/nml/resources)** を参照。

### 雲が出た瞬間に落ちる

- **症状**: 雲が初めて出たときに `Cloud.prepare()` で `NullReferenceException`。
- **原因**: `CloudLibrary` は起動時に一度で、`path_sprites` を `cached_sprites` に、`color_hex` を `color` にします。
- **解決策**: `add()` の後で両方とも自分でやる。**[雲と天気](#/nml/clouds)** を参照。

### 建物を置くと Index was out of range

- **症状**: 置いた瞬間に `Building.setAnimData()` で `ArgumentOutOfRangeException: Index was out of range`。
- **原因**: 建物のフレームは起動時にすべての建物ぶんプリロードされます。あなたの建物はフレーム一覧が空か、フォルダに `main_0.png` がありません。
- **解決策**: `sprite_path` を設定したら `shrine.loadBuildingSprites();`、フレーム名は `main_0`、`construction_0`、`ruin_0`、`mini_0`。**[カスタム建物](#/nml/custom-buildings)** を参照。

### 建物が画面に映っている間ずっと例外が出る

- **症状**: `DynamicSprites.getRecoloredBuilding()` で `NullReferenceException` が何百回も、画面に映っている間は毎フレーム。
- **原因**: 建物を持ち主の色に塗るアトラス `atlas_asset` は、起動時に `checkAtlasLink()` で紐付けられます。複製には残りません。
- **解決策**: `shrine.atlas_asset = AssetManager.dynamic_sprites_library.get(shrine.atlas_id);`

### 建物があるとミニマップが例外を出す

- **症状**: ミニマップを描き直すたびに `Building.getColorForMinimap()` で `NullReferenceException`。
- **原因**: ミニマップの点は建物フォルダの `mini_0.png` から作られますが、それがありません。
- **解決策**: `mini_0.png` を追加する。建物が覆うタイル1つにつき1ピクセルで、`temple_human` から複製したものなら5x4。

### タイルは塗れるのに、マップの描画が例外を出す

- **症状**: 画面上のあなたのタイルごとに `WorldTilemap.getVariation()` で `NullReferenceException`。
- **原因**: `TopTileLibrary` は起動時に `tiles/<id>/` のPNGを `sprites` に読み込みます。
- **解決策**: `addVariation()` で自分で読み込む。**[タイルと地形](#/nml/tiles)** を参照。

### あなたのタイルに動物を出すと落ちる

- **症状**: `Subspecies.generateName()` で `NullReferenceException`。あなたのタイルの上で、動物のときだけ。
- **原因**: 草タイルの複製は `is_biome = true` を保ちますが `biome_asset` は失います。これは起動時に `linkAssets()` で紐付けられるものです。動物は種名にバイオームを付けます。
- **解決策**: `moss.biome_asset = AssetManager.biome_library.get(moss.biome_id);`

### ドロップが見えないまま落ちる、または飛び道具が例外を出す

- **症状**: ドロップが何も描かれずに落ちる、または `QuantumSpriteLibrary.drawProjectiles()` で `ArgumentOutOfRangeException`。
- **原因**: ドロップ、飛び道具、ステータス、建物、手に持つリソースは `getSpriteList()` で絵を読み、これはフォルダの *中の* フレームを返します。PNG単体は空の一覧になります。
- **解決策**: 1フレームでもアニメーションごとにフォルダを1つ：`drops/hello_ember/hello_ember_0.png`。**[スプライトとリソース](#/nml/sprites-and-resources)** を参照。

### 飛び道具の ArgumentNullException でログが埋まる

- **症状**: 飛び道具が飛んでいる間、`ProjectileManager.updateProjectiles()` で `ArgumentNullException: Value cannot be null` が何千回も。
- **原因**: 撃ち手のいない飛び道具には王国（kingdom）がなく、マネージャーは毎フレーム王国を辞書のキーに使います。
- **解決策**: 王国を与える：`pForcedKingdom: World.world.kingdoms_wild.get("nature")`、ゲーム自身の中立の持ち主です。

### パワータブが出てこない

- **症状**: `PowersTab.setNewWidth()` で `NullReferenceException`、タブがなく、パワーもない。
- **原因**: `OnModLoad` の中で `recalc()` を呼んだ。タブ自身の `Start()` がまだ走っていないので親が `null` のままで、例外がステージごと止めます。
- **解決策**: タブはロード時に作り、配置は `Update()` から。**[パワータブとボタン](#/nml/power-buttons)** を参照。

### 設定ウィンドウに生のidが出る

- **症状**: ログに `LocalizedTextManager: missing text: strike_radius Description`。
- **原因**: NMLは設定の各行に2つのキーを求めます。ラベル用の `<id>` と、ツールチップ用の `<id> Description`（スペースと大文字のD）。
- **解決策**: 両方を `Locales/en.json` に追加。**[mod設定](#/nml/mod-config)** を参照。

### ワールド挙動を追加した後、毎フレーム例外エラーが発生する

- **症状**: Mod ロード直後から `MapBox.updateWorldBehaviours()` で毎フレーム `NullReferenceException` が発生する。
- **原因**: ワールドはアセットごとに1つのタイマーを保持しますが、これはマップが初起動した際に生成されます（Mod が読み込まれる前です）。追加したアセットにはタイマーが存在せず、ループ処理がそのまま呼び出してしまいます。
- **解決法**: `add()` の直後に `behaviour.manager = new WorldBehaviour(behaviour);` を実行します。詳細は **[世界の時代とワールド挙動](#/nml/world-ages)** を参照してください。

### 災害がワールドログに書き込もうとした際にクラッシュする

- **症状**: `WorldLog.logDisaster()` から呼ばれる `WorldLogMessage` のコンストラクタ内で `NullReferenceException` が発生する。
- **原因**: `world_log` に指定するのはテキストキーではなく `WorldLogAsset` の ID です。未登録の ID を指定すると `null` が返り、メッセージ構築処理がクラッシュします。
- **解決法**: その ID で `$basic_disaster$` をクローンし、`locale_id` を設定してください。詳細は **[自然災害](#/nml/disasters)** を参照してください。

### action を設定していない災害が抽選された瞬間にクラッシュする

- **症状**: 災害の抽選があなたの自作災害に当たった際、`WorldBehaviourActions.updateDisasters()` で `NullReferenceException` が発生する。
- **原因**: 災害抽選システムは null チェックを行わずに `action` を呼び出します。`spawn_asset_unit` を指定しただけでは何も実行されません。
- **解決法**: `action` に `AssetManager.disasters.simpleUnitAssetSpawnUsingIslands` を代入するか、独自のアクションを記述してください。

### 指導者が自作の陰謀を検討した瞬間にクラッシュする

- **症状**: `PlotAsset.checkIsPossible()` で `NullReferenceException` が発生する。
- **原因**: 指導者が陰謀を評価するたびに、`check_is_possible` が null チェックなしで呼び出されます。
- **解決法**: 必ず設定してください。条件がない場合は単に `true` を返します。詳細は **[陰謀・計画](#/nml/plots)** を参照してください。

### 自作の意思決定、陰謀、遺伝子、武器が存在するのにゲーム内で誰も使わない

- **症状**: エラーは出ない。アセットはライブラリに存在するが、ゲームが一度も選択しない。
- **原因**: ゲームは起動時に構築された特定のリストから抽選します：`basic_plots`、意思決定リスト、遺伝子変異プール、武器プール、時代（world age）のスロットプールなど。あなたの追加アセットは起動後に追加されたため含まれていません。
- **解決法**: ゲームが実際に読み込むリストに追加してください。各ページに対応するリストが記載されています：**[カスタム AI](#/nml/custom-ai)**、**[陰謀・計画](#/nml/plots)**、**[亜種特性](#/nml/subspecies-traits)**、**[カスタムアイテム](#/nml/custom-items)**、**[世界の時代とワールド挙動](#/nml/world-ages)**。

## 自分の環境では動くが、他の人の環境で動かない

定番の「自分の環境では動く」。違いはたいていコードではなく、あなたの環境設定にあります :PES5_Hmmmm:。

### `CS0122: inaccessible due to its protection level`

- **症状**：動いているModからコピーしたコードがコンパイルできない：`addStatusEffect`、`getHit`、`_localized_text`、`addBuilding`。
- **原因**：それらは `internal` です。NMLはあなたの `Code/*.cs` を、自前の**publicize済み**コピー（`StreamingAssets/Mods/NML/Assembly-CSharp-Publicized.dll`）に対してコンパイルするので、普通のソースModならそのまま動きます。このエラーが出るのは、Visual Studioで、それらを隠している通常の `Assembly-CSharp.dll` に対して自分の `.dll` をビルドしたときです。
- **解決策**：プロジェクトでそのpublicize済みコピーを参照するか、publicな方法を使ってください：

| 代わりに | これを使う |
| --- | --- |
| `actor.addStatusEffect("x", 20f)` | `World.world.statuses.newStatus(actor, AssetManager.status.get("x"), 20f)` |
| `actor.getHit(5f, ...)` | `actor.changeHealth(-5)` |
| `LocalizedTextManager.instance._localized_text[k] = v` | `LM.Add("en", k, v)` の後に `LM.ApplyLocale(false)` |

### 自分のPCでは動くのに相手のPCでは何も起きない

- **症状**：Modは読み込まれるのに中身がない、または1行目でエラーを出すという報告が来る。
- **原因**：ほぼ必ず次の4つのどれかです：ユーザー名入りのハードコードされたパス；*フォルダー*ではなくModの*中身*をzipにした；リリースの間に `GUID` が変わった；`Code/` を古い `.dll` と一緒に配布した。
- **解決策**：パスは `GetDeclaration().FolderPath` から作りましょう。フォルダーをzipにします。`GUID` は一度決めたら絶対に変えません。`Code/` **か** `.dll` のどちらかを配布し、両方は絶対に入れません。

## 最初は動くが、後から壊れる

じわじわ来るタイプ。昨日まであなたのModは問題なく動いていて、何も変わっていません :PES2_Shrug:。

### 他のModを入れると自分のコンテンツが消える

- **症状**：特定の別Modを入れると、あなたの特性が消える。ログにはとっくにスクロールで流れた1行：`duplicate asset - overwriting...`
- **原因**：IDの名前空間はライブラリごとに1つだけで、バニラとすべてのModで共有されています。最後の登録が勝ち、読み込み順はあなたが決められません。
- **解決策**：すべてのIDに接頭辞を付けましょう：`hello_swift` にし、`swift` は絶対に使わない。`if (AssetManager.traits.has(SWIFT)) return;` でガードします。バニラの内容を*変えたい*なら、置き換えを追加するのではなく、`get()` で取り出してその場で編集してください。

### Mod 読み込み中に `World.world` でクラッシュする

- **症状**：マップに触れる最初の行でクラッシュする。
- **原因**：`OnModLoad` はワールドが存在する前に実行されます。アセットライブラリは準備できていますが、ワールドはまだです。
- **解決策**：登録は `OnModLoad` で行い、ワールドには `Update()` から、`if (!Config.game_loaded) return;` と `World.world`、`World.world.units`、`MapBox.instance` のnullチェックの後ろで触れてください。

### 関係のないユニットにデータが適用されてしまう

- **症状**：セーブを読み込んだり新しいワールドを作ったりした後、無関係なユニットが取り憑かれたように動く。
- **原因**：ユニットのIDは**ワールドごと**で、最初から振り直されます。`Actor` オブジェクトを持ち続けるのはもっと悪く、死んだアクターはプールされて再利用されるので、参照は決してnullにならず、今は別人になっています。
- **解決策**：ワールドが変わったことに気づいて、全部捨ててください。ワールドの時間が巻き戻ったかどうかが一番安い合図です：

```csharp
double now = World.world.getCurWorldTime();
if (_lastWorldTime >= 0.0 && now < _lastWorldTime - 1.0) MyRegister.Clear();
_lastWorldTime = now;
```

### セーブ＆ロード後にすべて消えてしまう

- **症状**：ユニットはバニラの挙動に戻っているのに、あなたの特性はまだ付いている。
- **原因**：シリアライズされるのはゲーム自身のデータクラスだけで、あなたのstaticな辞書は保存されません。特性はIDとして保存され、**読み込み時にライブラリにないIDは黙って捨てられます**。つまり、無効にして、読み込んで、有効に戻すと、すべてのユニットから特性が外れます。
- **解決策**：生き残る目印として特性を使い、そこから復元しましょう：`trait.action_on_augmentation_load = (pActor, pTrait) => MyRegister.Restore(pActor);`
- **または**：状態をユニット自体に持たせてください。ユニットのカスタムデータ保存領域は一緒に保存されます：**[データを覚えておく](#/nml/saving-data)** を参照。

### ユニットが集団でフリーズする

- **症状**：ユニットの集団が動かなくなり、その集団がフレームごとに変わる。例外はフレームごとに1つで、何千もではない。
- **原因**：ユニットごとのループにはtry/catchがありません。ユニット *i* で例外が出ると、そのフレームではそれ以降のすべてのユニットが飛ばされます。
- **解決策**：すべてのパッチと、すべての独自ビヘイビアの `execute` の本体をtry/catchで囲み、失敗したら `BehResult.Stop` を返してください。

### Harmony パッチの半分が適用されていない

- **原因**: `PatchAll` は1つでも解決できないクラスがあると処理を中断します。
- **解決策**: クラス単位で個別にパッチを適用してください（**[Harmony パッチ](#/nml/harmony-patches)** 参照）。

### `updateStats` パッチが他のプレイヤーの環境で落ちる

- **原因**: `updateStats` はマルチスレッド（並列処理）で実行されます。
- **解決策**: そのメソッド内ではユニット自身の数値変更のみを行い、グローバルな処理は `Update()` に送ってください。

### `getHit` をパッチしたのに建物がダメージを受ける

- **原因**: `getHit` は `Actor` と `Building` の両方にオーバーライドが存在します。
- **解決策**: 必要な具象クラスごとにパッチを当ててください。

### 自分の Prefix が他の3つのModを壊してしまった

- **症状**：「君のModがModXを壊した」。ログには何もなく、Xの作者も単体では再現できない。
- **原因**：`false` を返すと、元のメソッド**と、あなたの後に来る他のModのパッチすべて**がスキップされます。`updateStats` では、古いキャッシュ済みフラグがユニットに永遠に残ることにもなります。
- **解決策**：Prefixで中止するより、Postfixで調整（`__result *= 0.5f`）する方を選んでください。どうしても中止するなら一番狭いメソッドにし、関係ないケースではすべて早めに `return true` してください。

### ユニットが立ち尽くす、または毎フレームクラッシュする

- **症状**：タスク名のないユニットが1体固まる、または毎ティックのスタックトレース。
- **原因**：未知の**タスク**IDは、黙ったまま永遠に何もしません。未知の**ジョブ**IDは毎ティックのクラッシュです。
- **解決策**：読み込み時にIDを一度だけ検証し、タスクはそれを並べるジョブより先に登録し、確認していないIDを `next_job_delegate` に渡さないでください。

### カスタムAIがいつの間にかバニラに戻ってしまう

- **症状**：しばらくすると、あなたの登録簿には載っているのに、一部のユニットがバニラのAIに戻っている。
- **原因**：アクターはプールされています：「新しい」ユニットは、ジョブのデリゲートがリセットされたばかりの再利用オブジェクトです。戦闘でもリセットされます。
- **解決策**：一度だけでなく、自分のタイミングで何度も設定し直してください：`if (pActor.ai.next_job_delegate != MyAI.NextJob) pActor.ai.next_job_delegate = MyAI.NextJob;`

### ゲームが1秒に4回カクつく

- **症状**：平均FPSは問題なさそうなのに、ゲームがリズミカルにカクつく。特に重い関数は1つもない。
- **原因**：すべてが同じティックで考え、ユニットは今の行動（behaviour）が終わったときにしか進まないので、みんな同時に終わります。
- **解決策**：`execute` の中ではなく、自分のタイマーで考えてください。集団を区切り、1回につき1区切りだけ処理します。リストは事前に確保し、LINQ、ラムダ、`Debug.Log` はその経路から外してください。

### ウィンドウ背後のマップをクリックしてしまう

- **症状**：プレイヤーがパネルのコントロールをクリックすると、その下にユニットが出現する。
- **原因**：`GraphicRaycaster` のないcanvasは描画はされますが、クリック判定はされません。そして `unselect_when_window` はゲーム自身のウィンドウしか知らないので、自作のパネルでは有効なパワーが解除されません。
- **解決策**：`Canvas` + `overrideSorting` + `sortingOrder` + `GraphicRaycaster` + 背景の `Image`、これを全部そろえます。ラベルには `raycastTarget = false`。ウィンドウが開いたら、パワーの解除は自分で行ってください。

### パネルを開くたびにメモリ使用量が増える

- **症状**：パネルを開くたびにメモリが段階的に増え、長時間のプレイで重くなる。
- **原因**：`Destroy(root)` はGameObjectのツリーを解放しますが、**あなたが**作った `Texture2D` や `Sprite` は別のオブジェクトで、誰も回収しません。
- **解決策**：自分で作ったものは破棄し、参照をnullにしてください。`SpriteTextureLoader` から来たスプライトは破棄**しないで**ください。それらは共有されています。

### 新しいデフォルト設定が既存プレイヤーに反映されない

- **症状**：`default_config.json` のデフォルト値を変えたのに、既存のプレイヤーは古い値のまま。新規インストールは問題ない。
- **原因**：そのファイルは雛形にすぎません。実際の値は `mods_config\<UID>.config` にあり、これは**項目全体**を保存します。つまり、変えた範囲や名前を変えたコールバックも覆い隠されます。
- **解決策**：そのファイルを消した状態でテストしてください。既存ユーザーのために範囲やコールバックを変える必要があるなら、古い項目を編集するのではなく、新しい `Id` を追加してください。

### 設定スライダーを動かしてもコールバックが走らない

- **症状**：その行は動き、値も保存されるのに、メソッドが一度も呼ばれない。
- **原因**：コールバックは `Namespace.Type:MethodName` で、メソッドは **static** でなければならず、引数は型と一致していなければなりません（`INT_SLIDER` → `int`、`SLIDER` → `float`、`SWITCH` → `bool`、`TEXT` → `string`）。
- **解決策**：名前空間を含め、staticにし、型を合わせてください。変更が反映されるのはドラッグ中ではなく、ウィンドウを**閉じた**ときです。
