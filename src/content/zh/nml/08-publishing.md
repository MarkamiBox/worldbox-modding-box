# 发布模组 :wbfireworks:

你的模组现在可以跑了。是时候放出去让其他玩家把它玩坏了。

WorldBox 模组主要可以发布在两个地方，但它们的热度截然不同：

| | |
| --- | --- |
| **[GameBanana](https://gamebanana.com/games/11196)** | WorldBox 真正的模组生态中心。任何人都可以从这里下载，包括没有在 Steam 上购买游戏的玩家 |
| **Steam 创意工坊** | 内置于 NML 中，但上面的模组要少得多 |

优先在 GameBanana 上发布。如果之后有兴致，再去创意工坊镜像一份。

## 打包模组

GameBanana 上的上传包就是一个包含**你模组文件夹的 zip 压缩包**，仅此而已。压缩包内部的根目录必须是包含 `mod.json` 的那个文件夹：

```text HelloBox.zip
HelloBox/
├── mod.json
├── icon.png
├── default_config.json
├── Locales/
├── GameResources/
└── Code/
```

是**文件夹本身的 zip 包**，而不是直接把*文件夹内部的所有文件*全选打包。玩家解压到自己的 `Mods/` 目录后，得到的结构应该是 `Mods/HelloBox/mod.json`。如果解压出来变成了 `Mods/mod.json`，他们就会在评论区发帖说你的模组根本无法加载 :PES_Facepalm:。

**剔除一切**运行时不需要的冗余文件：`.git/`、`bin/`、`obj/`、`.vs/`、你的 `.sln` 工程文件以及私人开发笔记。如果你随包分发预编译好的 `.dll`，请用它**替代** `Code/` 源码目录，不要把过期的源码残留和编译包混在一起。

## 上传至 GameBanana

1. 注册一个账号，然后前往 **[WorldBox 游戏主页](https://gamebanana.com/games/11196)**。
2. 点击 **Add → Mod**。
3. 填写名称、描述和分类。分类比你想象的更重要：玩家全靠分类来筛选发现你的模组。
4. 上传 zip 包，并至少上传一张**模组在游戏里实际生效的截图**。不要只放你的图标或者模组列表界面。
5. 在描述中开门见山地说清楚：它增加了什么、它需要 **NeoModLoader**、以及它与哪些模组存在冲突。

日后更新同样在该页面点击 **Edit → Files**。添加新的 zip 包，写一行更新日志，并同步提高 `mod.json` 中的 `version` 版本号。保持 GameBanana 上的版本号与 `mod.json` 一致不需要任何成本，却能彻底省去所有“我到底装的是哪一版”的疑惑。

> [!TIP] 一张截图胜过千言万语
> 玩家通常只根据封面缩略图做决定。一张清晰展示你模组新增内容的实机截图，带给你的下载量远胜于全站文笔最优美的长篇大论 :PES_Camera:。

## Steam 创意工坊发布流程

上传到 Steam 创意工坊的操作是在**游戏内部**完成的，而打开上传窗口的方式堪称这个圈子里最抽象、最受诅咒的 UI 交互设计 :kekw:。

1. 在游戏内打开 **Mods** 模组列表窗口。
2. 对准你模组的**图标**连续猛点正好 **8 次**，每次点击间隔不要超过 1 秒。
3. 耐心等待大约 3 秒钟。
4. 上传弹窗就会冒出来。

如果什么都没发生，说明你点得太慢了，或者你点到的是整行背景而不是图标本身。

全新的 NML 模组列表界面还在选中模组后提供了快捷操作按钮——可一键在资源管理器中打开模组文件夹、启用/禁用或热重载代码，但点击图标 8 次的神秘仪式依然是呼出 Steam 上传界面的唯一途径 :PES2_Shrug:。

| 字段 | 填写内容 |
| --- | --- |
| 上方输入框 (`fileID`) | **初次发布时务必留空**。更新已有模组时，粘贴你创意工坊物品（item） URL 链接里的数字 ID |
| 下方输入框 | 更新日志。可以留空，发布后也能在创意工坊网页端随时编辑 |

这就是初次发布与后续更新的全部区别：空的 `fileID` 会新建一个工坊物品，填写的 ID 则会覆盖替换已有物品。

### 首次身份认证

首次向创意工坊上传模组时会要求进行身份认证。有三种途径：

- **Discord**：前往官方 WorldBox Discord 服务器，向管理员申请获得 `Modder` 专属身份组。
- **GitHub**：加入 `WorldBoxOpenMods` 组织。发送邮件，主题注明“WorldBoxOpenMods”，附上你的 GitHub 用户名和模组，等待最长约一周的审核。
- **直接跳过**：你的模组会带着 `Unverified Mods`（未认证模组）标签强制上传。功能完全正常，只是曝光度稍低一些。

## 在点击上传发布前的最后检查

- **`mod.json` 是你的门面。** `name`、`author`、`version`、`description` 是玩家第一眼看到的东西。每次发布都要递增 `version`，且**初次上传后绝不要修改你的 `GUID`**：它是模组的身份证号，玩家的设置存档以它命名，其他模组可能也依赖于它。
- **确保 `icon.png` 存在且好看。** 在创意工坊里这也是玩家要连续狂击 8 次的地方，至少让它赏心悦目一点。
- **模组必须能够在任意目录名下正常工作。** 绝不要硬编码 `C:\Users\YourName\...` 这类固定路径。使用 `GetDeclaration().FolderPath`。这是导致“作者自己电脑上跑得好好的，别人那里一律报错崩溃”的最常见原因 :PES2_Bruh:。
- **认真排查一次你自己的干净日志。** 启动游戏，载入一个世界，游玩两分钟，在 `Player.log` 中搜索你的模组前缀并搜索 `Exception`。发布时必须保证零报错。
- **删除设置文件后再测试一遍。** 删掉 `mods_config/<GUID>.config`，以便亲自验证全新玩家首次加载时拿到的默认体验。
- **与其他常见模组一起测试。** 如果你 patch 了某个方法，很大概率别人也在 patch 它。
- **在全新空存档上测试。** 你注册的所有资源，都必须在载入任何引用了它们的存档之前完成初始化。

## Dependencies

如果你的模组依赖其他模组，请显式声明，而不是任由缺失类型导致游戏闪退：

```json mod.json
{
  "Dependencies": ["com.otherperson.coolmod"],
  "OptionalDependencies": ["com.someone.niceextra"],
  "IncompatibleWith": ["com.someone.rivalmod"]
}
```

NML 会自动处理加载顺序并在缺少前置时提醒玩家，这比在第一行代码就弹一个空指针异常要优雅体面得多。

## 发布之后

评论区里收到的反馈基本上可以精准归为三类：没附带任何日志的“模组坏了”、一个连你自己都没想到的真正绝妙的点子、以及向你催更联机模式的玩家 :PESgn_DidIAsk:。

认真回复第二类。针对第一类，置顶一条评论告诉大家去哪里找 `Player.log`（参见 **[日志与调试](#/nml/logs-and-debugging)**），因为没有日志的 Bug 反馈，开发者根本无从下手。

还有，欢迎你。每一个新模组都让这个小社区少一点像墓地，一周出五个，那就是模组的黄金时代（world age） :PES5_CrazyPog:。
